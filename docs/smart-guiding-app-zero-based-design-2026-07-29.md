# 스마트 가이딩 앱 — 제로베이스 설계 (2026-07-29)

> 기존 구현을 참조하지 않고 백지에서 다시 설계한 문서. 목표는 **영어를 한 마디도 못 하는 관광전문 택시기사가 스몰그룹 투어를 이끌고, 나아가 버스기사가 40인 단체를 이끄는 것**이며, 그 과정에서 손님이 느낄 불편과 불안을 설계로 제거한다.
>
> 이 문서는 설계 단일 기준이다. 구현 계획이나 WBS는 포함하지 않는다.

---

## A. 명제

**앱은 가이드를 대체하지 않는다. 이미 가이드인 사람에게 없는 기관 하나 — 언어 — 를 이식한다.**

관광전문 택시기사는 서비스 의지가 있고, 어디서 세워야 사진이 잘 나오는지 알고, 손님이 지치면 알아챈다. 그 사람에게서 발화권을 뺏어 앱에 주면 가진 자산 중 가장 비싼 것을 버리는 설계가 된다.

여기서 파생되는 단 하나의 규칙:

> **모든 안내는 "기사가 한 행동"으로 귀속된다.** 앱이 알아서 떠드는 게 아니라 기사가 판단하고 앱이 대신 말한다. 손님 화면에도 그렇게 뜬다 — *"김민수 기사님의 안내"*. 자동 발사는 폴백이지 주경로가 아니다.

### A-1. 가이드 업무 분해와 이전 대상

| 가이드 업무 | 기사 수행 가능성 | 이전처 |
|---|---|---|
| 동선·시간·차량 통제 | 가능 | 기사 + 앱이 시계를 소유 |
| 해설·스토리텔링 | 불가 | **사전 제작 콘텐츠** |
| 임의 Q&A | 불가 | **원격 유자격자** |
| 정서적 돌봄 | 비언어로 부분 가능 | **의전 의례 + 신호 UI** |
| 사고·돌발 처리 | 물리적으로 가능 | 기사 + 원격 |
| 현장 판매·현금 | 민망함이 장벽 | **앱이 대신 말함** |
| 안전·권위 | 부분 | **시스템이 정책을 집행** |

핵심은 해설과 Q&A의 분리다. **가이드 발화의 90%는 예측 가능하고, 예측 가능한 것은 실시간 번역할 이유가 없다.** 실시간 번역은 나머지 10%에만 쓴다. 대부분의 경쟁 제품이 이걸 거꾸로 해서 소음·터널·사투리에 취약한 STT/MT 위에 제품 전체를 얹고 무너진다.

## B. 설계 원칙

1. **결정론 우선.** 미리 만든 것 > 실시간 생성한 것. 오역 한 번이 좋은 번역 100번을 지운다.
2. **오프라인이 기본값.** 터널·해안·산간에서 가이드가 침묵하면 신뢰가 죽는다. 하루치 전체를 탑승 시점에 내려받는다.
3. **채팅이 아니라 방송.** 대화는 상호성을 약속하고, 기사는 그 약속을 지킬 수 없다.
4. **앱은 꺼져 있어야 성공이다.** 화면 켜짐 시간은 낮을수록 좋은 지표다.
5. **나쁜 소식을 먼저, 자동으로.** 신뢰를 만드는 건 사과가 아니라 선제 고지다.
6. **모르면 모른다고 한다.** 자신 있게 틀린 ETA는 "확인 중"보다 나쁘다.
7. **기사를 감시하지 말고 보호하라.** 감시 장비로 느끼는 순간 안 쓴다.
8. **약속은 지킬 수 있는 것만 표시한다.** 응답 시간·출발 시각·커버 언어 전부. (§F 감사에서 이 원칙 위반이 가장 많이 나왔다.)

## D. 4레이어 구조

### D-A. 제작 레이어 — 투어는 공연이 아니라 상품이다

- 스팟마다 언어별 60~180초 해설. 사람이 쓰고 교정한 대본 + TTS.
- **이동 구간 해설이 진짜 차별점.** 스팟 사이 20분이 가이드 유무의 체감 격차가 가장 큰 구간인데 다들 비워둔다.
- 트리거는 도착 감지(지오펜스 + 속도 + 체류)지만, **발사 주체는 기사**(§D-B의 발화 대기열).
- 깊이 2단(짧게/깊게), 아동 버전, 접근성 버전.
- 하나의 내레이터 페르소나를 하루 종일 유지. 이름을 준다.

**TTS 품질 게이트 (D2에서 파생)**
- **사전 합성 후 파일 배포.** 런타임 합성 금지 → 오프라인·지연·비용 동시 해결.
- **슬롯 문장.** "12분 지연되어 우도가 20분 줄어듭니다"는 사전 합성이 불가능하다. 고정 조각 + 숫자/장소 슬롯으로 쪼개고, 숫자 오디오(1~120분, 시각 전체)를 미리 만들어 이어붙인다.
- **발음 사전이 자산.** 성산일출봉·주상절리·해녀·오메기떡을 각 언어 TTS가 어떻게 읽는지의 테이블. 없으면 첫 문장에서 싸구려 티가 난다.
- **대본 금지 목록**: 마크다운·별표·괄호·URL·이모지·약어. 숫자·연도·통화·단위는 읽는 형태로 미리 풀어 쓴다.
- **정보는 TTS가, 관계는 사람 목소리가.** 기사 본인 한국어 5초 인사와 작별은 실제 녹음 + 자막. 지연 사과도 기계 목소리로 하지 않는다.

### D-B. 지휘 레이어 — 투어 시계

투어를 모두가 같이 보는 상태 기계로 만든다.

```
대기 → 이동 → 도착 → 자유시간(카운트다운) → 집합 → 인원확인 → 출발
```

**손님 화면은 "지금 카드" 하나.** 언제 열어도 네 가지에 답해야 한다.
1. 지금 무슨 일이 일어나는 중인가
2. 다음 일이 몇 시에 일어나는가
3. 내가 지금 뭘 해야 하나 — **"아무것도 안 하셔도 됩니다"도 정식 상태**
4. 문제가 생기면 어느 버튼인가

불안은 곧 가까운 미래에 대한 불확실성이다. 이 카드 하나가 불안의 80%를 없앤다. 단 **상태별로 표시 항목이 달라야 한다** (§F-12) — 이동 중엔 신호 3개, 자유시간엔 카운트다운·집합·길잃음.

**발화 대기열 (Say Queue)** — 이 설계의 중심 장치

기사 화면에 지금 할 만한 말 2~4개가 항상 대기한다. 위치·속도·시각·날씨·다음 일정·손님 신호·직전 발화가 무엇을 띄울지 결정한다.

- **필수 항목**(집합 시각, 안전, 결제)은 T초 내 미조작 시 자동 발사. 재량 항목은 영원히 기다린다.
- 이미 말한 건 사라진다.
- **4개를 넘으면 실패다.** 기사가 안 읽는다.

부수 효과: 신입 기사가 첫날부터 베테랑처럼 말하고, 베테랑은 절대 안 잊는 사람이 된다.

**자유시간 카운트다운** — 킬러 기능. 기사가 "여기서 40분"을 한 번 누르면 전원 폰에 실시간 카운트다운 + 집합 장소의 **실제 사진** + 각자 위치 기준 도보 시간. 개인별 알림 시각이 다르다.

**인원 확인** — §F-2 수정 반영. 2상태가 아니라 **3상태**다.

| 상태 | 근거 | 표시 |
|---|---|---|
| 확인 | 문 통과 근거리 태그(도어 비콘 / 좌석 QR) | 초록 |
| 추정 | 차량 비콘 반경 안이지만 미태그 — 옆 카페일 수 있음 | 노랑 + 육안 확인 요청 |
| 미확인 | 신호 없음(배터리·기내모드) | 회색. **절대 미탑승으로 표기하지 않음** |

**침묵 신호 버튼** — 화장실 / 배고파요 / 춥·더워요 / 사진 / 몸이 안 좋아요 / 천천히 / 길잃음. 손님은 말 걸기를 부끄러워한다. 버튼이 그 사회적 비용을 0으로 만든다. **정서 노동을 UI로 구현한 것.**

**신호 → 응답 왕복을 닫는다.** 신호마다 기사 원탭 응답 세트가 붙는다.

| 신호 | 원탭 응답 |
|---|---|
| 화장실 | 5분 뒤 휴게소 / 바로 세움 / 다음 장소에 깨끗한 곳 |
| 배고파요 | 12:30 식사입니다 / 지금 간식 사러 |
| 추워요 | 온도 올릴게요 (+실제 조작) |
| 사진 | 네, 저기서 찍어드릴게요 |
| 몸이 안 좋아요 | 자동 에스컬레이션 → 코디 + 증상 카드 |

손님이 사는 것은 "말이 통한다"가 아니라 **"내가 신경 쓰이고 있다"**이다.

**단, 주행 중에는 다르다** (§F-1 수정). 속도 20km/h 초과 시 기사 화면은 잠기고, 신호는 한국어 음성으로 읽어준다. 응답은 화면 아무 데나 한 번 = 대기열 1순위 응답 발사. 손님에게는 **"받았습니다 — 운전 중이라 곧 답합니다"가 자동으로 먼저** 나가고, 3초 응답 약속 표기도 손님 화면에서 내려간다.

### D-C. 사람 레이어 — 보이지 않는 가이드 (사장님)

- 손님 화면에 실명·사진·응답 시간이 항상 떠 있다. **써보지 않아도, 사람이 존재한다는 사실만으로 가치의 90%가 발생한다.**
- 3단계 에스컬레이션: 번역 채팅 → 통화 → 손님·코디·기사 3자 통역.
- **선제 개입.** 25분 지연을 보면 컴플레인 전에 사과와 조정안을 먼저 보낸다.

**1인 제약이 콘솔을 지배한다.**
- 모바일 우선. 화면엔 **지금 나를 필요로 하는 것 1개**.
- 정상은 무음. 울리면 진짜다.
- **부재 설계 필수.** 상태 3단(대기중 / 지연응답 / 야간)이 **손님 화면 문구를 실시간으로 바꾼다** (§F-7). 정적인 "1분 내 답장"은 못 지키는 순간 앱 전체를 무너뜨린다.
- **"이 답변을 문구 덱에 저장" 버튼.** 초기 콘텐츠 파이프라인은 사실상 이것 하나다.
- 확장 슬롯: 파트타임 유자격자가 붙어도 그대로 쓰이게 배정·인수인계를 처음부터 구조에 넣는다.

**병목 완화** (§F-6): T+7 1차 접촉은 사람이 아니라 **자동 음성 콜**(손님 언어 TTS + 위치 안내)이고, 무응답 시에만 사장님. 버스는 **일행 리더 우선**. 코디 큐는 출발 임박 순 우선순위.

### D-D. 기사 계기판

- **3탭 이내, 타이핑 0, 외국어 노출 0.** 기사가 생각해야 한다면 설계가 실패한 것이다.
- 화면은 묻지 않고 지시한다: "다음 성산일출봉 09:40 · 주차 B · 하차 40분".
- 지연 코칭은 원탭 조정안 3택 → 선택 즉시 전원 언어별 자동 고지.
- **기사는 어떤 상황에서도 외국어 통화를 하지 않는다.** 미탑승 액션은 "전화"가 아니라 "코디가 전화" / "일행 리더에게".
- 비상 버튼: 코디 즉시 연결 + **동시에 손님 화면에 "확인 중입니다"**. 침묵이 혼란으로 읽히지 않게.

## E. 라우팅 테이블 — 누가 누구에게 말하는가

대부분의 앱이 "방 하나 만들고 다 같이 떠들기"로 만들어서 망한다.

| 방향 | 허용 채널 | 이유 |
|---|---|---|
| 손님 → 기사 | **구조화된 신호 버튼만** | 즉시·무오역·무부담 |
| 손님 → 코디 | 자유 텍스트·음성, 아무 언어 | 사람이 받으니 무엇이든 가능 |
| 기사 → 손님 | 발화 대기열(주) + 한국어 음성 번역(부) | 기사는 방송자이지 대화자가 아님 |
| 기사 → 코디 | 원탭 3자 통역 호출 | 기사가 주도권을 쥔 채 언어만 빌림 |
| 코디 → 전원 | 무제한 | 예외 처리 |

## F. 감사 — 발견된 결함과 수정

설계 전체를 재검토해 모순·병목·물리적 불가를 찾았다.

### P0 — 현장에서 즉시 깨지는 것

**F-1. 주행 중 3초 응답 약속이 안전과 충돌한다.**
→ 속도 20km/h 초과 시 화면 잠금 + 신호 음성 읽어주기 + 1버튼 응답. 손님에게 "받았습니다"가 먼저 나가고 3초 약속 표기는 내려간다. 잠금 해제는 정차 + 기어 P.

**F-2. 비콘 자동 카운트가 옆 카페 손님을 잡는다.** "38/40"이 한 번 틀리면 화면 전체가 못 믿을 것이 된다.
→ 3상태(확인/추정/미확인)로 전환. 비콘은 후보만 만들고 확정은 문 통과 태그. **전원 확인 전까지 출발 선언 잠금.**

**F-3. iOS Safari는 홈화면 추가 없이 푸시가 안 간다.** "설치 불필요"와 "카운트다운 알림"이 정면 충돌.
→ 알림 3중화. ① 브라우저 푸시(가능 기기) ② **SMS / WhatsApp 폴백** — T-5·T-0·T+7 세 시점만 ③ 화면 켜짐 시 인앱. 온보딩에서 알림 수신 방법을 명시적으로 고르게 한다. 버스는 차내 모니터 추가.

**F-4. 프라이빗 투어에 픽업 +10 출발 규칙을 적용할 수 없다.** 손님이 안 나오면 출발할 데가 없다.
→ **픽업 +10은 조인·버스 전용.** 프라이빗은 T+10에 "출발"이 아니라 **"일정 단축 시작"**으로 전환. 기다리되 손해는 손님 몫임을 사전 고지.

**F-5. 집단 지연과 개인 지각을 같은 사다리로 처리했다.**
→ 미복귀가 **일행 기준 과반**이면 집단 지연으로 판정 → 대기 15분 자동 연장 + 뒤 일정 자동 재계산 + 전원 고지. 그리고 해당 스팟 표준 체류시간을 학습 후보로 올린다. **과반이 늦으면 원인은 손님이 아니라 우리 시간 배분이다.**

### P1 — 1인 운영이 못 버티는 것

**F-6. 코디 전화 병목.** 버스 1대 × 스팟 6곳 = T+7 전화 6~9회. 소그룹이 겹치면 폰이 끊기지 않는다.
→ 자동 음성 콜 1차 + 일행 리더 우선 + 큐 우선순위 + **동시 운영 상한**(버스 1대 + 소그룹 N, N은 파일럿에서 실측).

**F-7. "replies in about 1 min"을 정적으로 박아뒀다.**
→ 실측 롤링 중앙값 + 코디 상태 연동으로 문구가 실시간 변경. 비커버 시간대는 AI 1차 응답 + **"AI가 먼저 답하고 사람이 확인합니다"** 정직 표기.

**F-8. 승인 큐를 매일 돌리면 즉시 막힌다.** 기사 20명 × 3건 = 60건.
→ **주 1회 월요일 배치.** 자동 1차 필터(중복·과단문·개인정보). 파일럿은 기사 3~5명. 그리고 **미승인이어도 본인 대기열에는 즉시 반영** — 내 노하우를 내가 쓰는 데 승인은 필요 없다.

**F-9. 유자격 언어는 EN/ZH인데 버스에 DE 손님이 있다.**
→ ① 비커버 언어는 AI 번역 + 영어 경유 ② 온보딩에서 정직 고지 ③ **버스 판매 시 언어 상한 설정**(미결정, §H).

### P2 — 정합성

**F-10. 별점 전면 공개는 역효과.** 낮은 별점 하나에 기사가 무너지거나 손님에게 따진다.
→ D5는 유지하되 **별점은 주 단위 집계만 공개, 개별 손님 연결 불가.** 텍스트 리뷰는 사장님이 필터링해 전달.

**F-11. 지연 문구는 사전 합성이 불가능하다.** → 슬롯 문장 + 숫자 오디오 사전 제작 (§D-A).

**F-12. "지금 카드 하나"인데 이미 조밀하다.** → 신호 버튼도 맥락에 따라 바뀐다. 이동 중 3개, 자유시간 3개.

**F-13. 낙오 택시비 전액 부담은 지각 인센티브가 된다.** → 전액 부담하되 **1인 1회**, 2회부터 본인 부담을 온보딩과 캡슐에 명시.

**F-14. OTA 손님은 온보딩을 못 볼 수 있다.** → OTA 메시지 채널로 링크 전달 + **미확인 손님은 기사 화면에 표시** + 리스팅 본문에 같은 문장 삽입.

**F-15. 배터리 나간 손님을 미탑승으로 오분류.** → 배터리 15% 미만 손님을 기사에게 표시(충전 케이블 안내), 신호 끊김은 "미확인"으로만 강등.

### G-4. 앱 밖 — 제품의 일부 (D4)

1. **전 좌석 충전** (C·라이트닝). 8시간 켜지는 앱은 충전 없이는 거짓말.
2. **차량 와이파이**, SSID 좌석 뒤 인쇄.
3. **도어 비콘 + 차량 비콘** 각 1개.
4. **종이 카드 1장** — QR + 집합시간 + 번호판 + 긴급번호. 아날로그 백스톱.
5. **비언어 의전 5종을 기사 체크리스트로 강제.** 눈맞춤·목례 / 문 열기 / 짐 받기 / 물 / 단체사진 + 앵글 손짓 / 우천 시 우산.

여기서 "충분한 앱"과 "가이드가 없었다는 걸 눈치 못 챈 투어"가 갈린다.

## H. 시간 규율 (D3 상세)

**공표 3회 + 매회 1번.** 예약 확인 / D-1 브리핑 / 탑승 온보딩, 그리고 자유시간 시작마다 "출발 15:40 — 15:55까지 대기 후 출발".

**집합 사다리 (관광지 +15)**

| 시점 | 동작 |
|---|---|
| T-15 | 알림. 도보 먼 사람·느린 그룹은 T-25 |
| T-5 | 알림 + 집합 사진 + 도보 경로 |
| T-0 | 미도착자만 강한 알림 |
| T+3 | 개인 알림 + 일행 리더 통지 |
| T+7 | **자동 음성 콜** → 무응답 시 코디 |
| T+12 | 최종 경고 + 낙오 안내 미리보기 |
| T+15 | **대기 종료 선언** + 낙오 캡슐 자동 발사 |

**앱이 정하는 것은 "출발"이 아니라 "대기 종료"다.** 실제 출차 타이밍은 기사(주차장 사정·안전). 그리고 과반 미복귀는 집단 지연 분기로 빠진다 (§F-5).

**시계는 하나.** 손님 폰에도 서버 시각이 뜬다. "내 시계로는 안 늦었다"를 원천 차단.

**예외 경로 명시.** 몸이 아프거나 미아 신호는 사다리에서 자동 이탈 → 코디 판단. **정책은 엄격하되 사고와 지각은 구별한다.**

**픽업(+10)은 앞을 두껍게.** T-30 준비 → T-10 "내려오세요" → T-0 도착 → T+5 최종 → T+10. 프라이빗은 출발이 아니라 일정 단축 전환 (§F-4).

## M. 이 설계의 가장 약한 고리

정직하게 적어둔다.

1. **알림 도달률.** F-3을 3중화로 막았지만, 폰을 안 보는 손님은 여전히 존재한다. 버스에서는 일행 리더와 차내 모니터가 최후 방어선이고, 이것도 실패하면 낙오가 난다.
2. **코디 1인.** F-6 완화책이 있어도 사장님이 아프거나 비행기를 타면 대체가 없다. 두 번째 유자격자 확보 전까지 이건 구조적 위험이다.
3. **TTS의 감정.** 사람 목소리 5초 규칙으로 덮었지만, 손님이 정말 힘든 순간(아픔·분실·다툼)에는 기계가 감당 못 한다. 그때는 반드시 사람이 나와야 하고, 그건 다시 2번으로 돌아간다.
4. **기사 채택.** 발화 대기열을 안 누르는 기사가 한 명이라도 나오면 그 투어는 조용한 택시가 된다. 대시보드 노출과 파일럿 코칭으로 막지만, 최종적으로는 배차와 연결해야 강제력이 생긴다(O4).
