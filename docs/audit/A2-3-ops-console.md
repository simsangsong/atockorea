## 1. 🔴 P2 즉시 수정 — SOS 사운드가 바쁜 날 **영구히 죽었다** (`opsShared.playSosSound`)

- **관측된 동작:** `playSosSound()`가 SOS마다 **새 `AudioContext`를 생성**했다. 브라우저는 동시
  AudioContext 수를 제한한다(Chrome ~6). 그래서 하루에 SOS가 예닐곱 건을 넘으면 `new AudioContext()`가
  **throw**하고, best-effort `catch`가 삼켜서 **그 세션 내내 모든 SOS가 무음**이 된다.
- **왜 P2인가(P1 아닌 이유):** 시각 알람(타이틀·파비콘 블링크)과 진동이 **주 채널**로 남아 있어
  SOS 자체를 놓치진 않는다. 사운드는 주석대로 "a bonus". 하지만 관제의 핵심 임무가 SOS 알림인데
  **가장 바쁜 날(SOS 다발) 사운드가 죽는다**는 건 실질 결함이다.
- **🔴 형제가 아는 것(여섯 번째):** 손님 `DriverConsole`은 진입 시 오디오를 언락하고 단일 컨텍스트를
  쓴다. 관제는 매번 새로 만들었다.
- **조치:** 단일 지연생성 컨텍스트 재사용 + `state==='suspended'`면 `resume()`. 누수 제거 +
  (벽걸이·무클릭 콘솔에서) 이후 상호작용 뒤 알람 복구까지 덤으로 얻는다.
  회귀: `__tests__/components/tour-ops/sosSound.test.ts` (12회 호출 → 컨텍스트 1개, resume 확인, API 부재 시 무예외).

## 2. 🔴 확인했고 문제없음 — SOS 파이프라인은 다층 방어다

1. **집계가 스냅샷 ∪ 라이브, 최신 우선**(`OpsApp:205-215`). 라이브 브로드캐스트와 REST 집계가 병합되고
   더 최신이 이긴다.
2. **같은 룸의 두 번째 SOS를 삼키지 않는다**(`sosKeys` = 룸+타임스탬프, `:221-228`). 한 룸에서 SOS가
   두 번 나도 각각 카드·사운드가 산다.
3. **사운드·진동은 SOS당 1회**(`sosSeenRef`), **블링크는 승인까지 지속**(`sosHandledRef`+`handledVersion`).
   승인 = 룸 열기 or SOS 탭. 알람이 조용히 꺼지지 않는다.
4. **실시간 끊기면 20초 백업 폴 + 5분 드리프트 리프레시**(W2.3). 브로드캐스트가 죽어도 SOS가 표면화된다.
   - 🟡 **P3 관찰:** 20초 폴은 "연결이 **down**일 때만" 돈다. 연결은 살아 있는데 **개별 SOS 브로드캐스트만
     유실**된 희귀 경우, 최악 표면화 지연이 **5분 드리프트**까지 늘 수 있다. 실시간이 실무상 신뢰되고
     down 케이스는 20초 폴이 덮으므로 P3로 둔다. 더 조이면 W2.3이 제거한 폴링 비용이 돌아온다.

## 3. 확인했고 문제없음 — 나머지 관제 면

1. **송신 실패가 재시도용으로 텍스트를 복원한다**(`OpsRoomDrawer:153` — *"never clobber what the agent has"*).
   손님 앱 A1.6이 틀렸던 침묵 실패가 여기엔 없다.
2. **리뷰 큐가 `failed`/`review_queued`를 구분**해 사람 처리 대상만 액션 가능으로 표시(`OpsReviewQueueView`).
3. **백로그 로드 실패는 스트림이 폴백**(`OpsRoomDrawer:73`) — 조용한 실패가 아니라 설계된 폴백(A1.6과 구분).
4. **`computeAttention`이 집계 행보다 스트림을 우선**(스트림이 더 신선, `attention.ts:112`) — 정체 방지.

## 4. 미검증 (실기기·역할)

- **다중 룸 동시 감시의 실부하**(수십 룸): 렌더·메모리·WebSocket 다중 구독은 실환경 부하 테스트 필요.
- **실기기 알림 권한·PWA 설치·백그라운드 SOS**(탭이 백그라운드일 때 사운드·블링크 도달) — 사람 게이트.
- **역할 강제**: A2.4가 가드 존재는 봤다. 관제 라우트가 admin/staff만 통과시키는지의 정확성은 라우트 역할 테스트.

## 5. 결론

관제 면은 견고하다. 단일 실질 결함은 **SOS 사운드 컨텍스트 누수**(바쁜 날 영구 무음)로, 이번에 수정했다.
SOS 다층 방어(실시간+폴+드리프트+시각+진동)는 모범이고, 송신 실패 복원·큐 구분도 성숙하다.
