## 세부 근거

**GR-001** — `timelineShare.ts:129` 주석이 스스로 말한다: *"`navigator.share` is what actually
reaches KakaoTalk / WhatsApp / Messages"*. 즉 공유 그릇은 검증돼 있고, 메시지 액션 시트에
숟가락만 얹으면 된다. 🔴 단 **무엇이 나가는가가 결정 사항이다** — 번역문·발신자명·사진 서명 URL
(몇 시간 뒤 404 + 능력 URL 유출, X17 이 사진을 뺀 바로 그 이유). 도입하더라도 **텍스트만**이 안전 기본값.

**GR-002** — 가이드 announce 는 새 방송을 만든다. 손님이 이미 물어본 것("집합 어디예요?")에 대한
좋은 답을 **기존 메시지에서 승격**하는 경로가 없어, 가이드는 같은 내용을 다시 타이핑한다.
엔진(NoticeBanner 계약·meeting_notice metadata)이 완비라 연결 작업은 작다. 단 공지 1장 불변식
(P-D8)과의 상호작용을 먼저 확인할 것.

**GR-005** — 반응 세트는 `ChatFeed.tsx:68` 리터럴 하나가 정본이라 **확장 자체는 소품**이다.
문제는 제품 판단: 5종은 "관제가 집계를 읽을 수 있다"는 절제이기도 하다(늘리면 시그널 대비 노이즈).
피커 도입보다 **세트 교체/추가(예: 👌🎉)** 가 하한 옵션.

**GR-008** — 재현: `grep -n "signRoomMediaBatch" app/api/tour-rooms/[bookingId]/media/route.ts`
(서명은 페이지 단위) · `docs/...X17` (사진 URL 을 공유에서 뺀 결정). 일괄 저장을 하려면
①서버 zip 스트림(서명 불요, 권한은 룸 세션) 이 정공법이고 ②클라이언트 순차 다운로드는 iOS 에서 깨진다.
