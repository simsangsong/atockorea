## §B 원칙 6 — 이 레포가 비싸게 배운 것들

**B-1. 측정 없는 주장 금지.** 모든 숫자에 **[실측] / [계산] / [추정]** 을 표시한다.
근거: "700KB" 주장이 **실측 423KB** 로 반증됐다. 그리고 §F 다이닝 MISS 예산 "8초"는 근거 없는 추정이었고
플랜이 스스로 그 자리에 *"예산은 측정 후에 쓴다"* 고 적었다.
🔴 **베이스라인에 추정이 한 줄 섞이면 다음 세션이 그 숫자로 회귀를 판정한다 — 없는 것보다 나쁘다.**

**B-2. 재현 불가능한 숫자는 먼저 재현 가능하게.** X7 에서 배운 것: 티켓이 지목한 우선순위 머리가
**이미 비어 있었다.** 티켓 설명은 *무엇을 할지*가 아니라 *무엇이 문제인지*로 읽는다.

**B-3. 감사와 수정을 분리.** 발견은 원장에만, 수정은 P6 에서. 앱 전면 점검(PR #660)이 이 구조로 28건 중 25건을 닫았다.

**B-4. 실사용 조건에서 잰다.** 손님은 **투어 중 · 휴대폰 · 4G**. `BUNDLE-BASELINE.md` 가 스스로
경고한다 — *"LCP는 스로틀 없는 localhost 값이라 절대치로 쓰면 안 된다."*

**B-5. 게이트가 없으면 조용히 회귀한다.** CJK 위반이 게이트 없는 동안 **576 → 583** 으로 늘었다.

**B-6. 지배 결함: 연결 문제.** 다섯 번 연속 "만드는 문제가 아니라 연결하는 문제"였다.
성능판 번역: **일을 안 하는 게 아니라, 틀린 쪽에서 하거나(클라이언트 vs 서버) 한 번 할 걸 N번 한다.**
🔴 **이 플랜 초안이 직접 이 함정을 밟았다** — 있는 자산 7개를 못 보고 "없다"고 썼다.

### P1 — 미측정 6개를 닫는다 🔴 이 트랙의 본체
`A0-perf-baseline.md §3` 이 각 항목의 착수 조건을 이미 적어 뒀다. 그 조건이 지금 갖춰졌다.

- **#7 Tier1** → 실 LLM 비용 발생 → **사장님 승인 후**, 소량 표본

### P2 — 스로틀 계층 신설 (기록된 `✗ 3G LCP` 청산)
`qa-bundle-baseline.mjs` 를 **확장**한다(신설 아님):
CDP `Network.emulateNetworkConditions`(4G: 하향 1.6Mbps · RTT 150ms) + CPU 4x 스로틀,
**INP · long task · TBT · CLS** 추가, `--check` 예산 모드, **실패 시 exit ≠ 0**.
⚠ 현재 워크 하니스들은 실패해도 `exit 0` 이다(qa-smartapp-walk 실측) — 게이트가 못 된다.
⚠ 수집기에 **비-공허 단정** 필수: 0개를 재면서 초록인 게이트를 만들지 않는다.

### P3 — 서버 42 라우트
p50/p95 · N+1 · 순차 await · `select('*')` · 외부 호출 타임아웃/캐시 · Supabase `get_advisors` 인덱스.

### P4 — 실시간·폴링 (손님 1명당 상시 비용)
`useTourRoomChannel` + `sseFallback` · `GuideConsole` **15초** · `VehicleLocationCard` **60초** [코드 실측].
재연결 폭주 방어를 **뮤테이션 테스트**로 확인 — 방어 주석은 증거가 아니다.
⚠ `BUNDLE-BASELINE.md` 가 "시뮬 불가"로 못 박은 것(동시 연결 상한 · SSE 증폭 · 콜드스타트 ·
실기기 백그라운드 타이머)은 **원장에 시뮬 불가로 남긴다.**

### P5 — 관제 54페이지
`/tour-ops` 는 이미 **JS 769KB · 총 3,460KB · 88 요청**[실측, 무스로틀]로 앱 최대다. 상위 10만.

### P6 — 원장 + 수정 + 상설 게이트
`docs/audit/PERF-LEDGER-2026-08.md`(증상 · 잰 값과 조건 · 원인 · 영향 사용자 · 난이도 · 게이트 가능 여부).
우선순위 **손님 > 스태프 > 관제**(손님만 4G·투어 중). 한 건 = 한 PR, 전후 같은 조건 재측정.

## §D 이미 알고 있는 후보 (P1 이전, 확정 아님)

1. 🔴 **룸 페이지가 서버 데이터 0** — `room/[bookingId]/page.tsx` 는 `force-dynamic` 인데
   서버에서 아무것도 안 읽고 `TourRoomClient` 만 렌더한다 [코드 실측].
   손님은 **HTML → JS → join → snapshot** 을 직렬로 기다린다. 4G 에서 이 직렬 대기가 얼마인지가 #4.
2. **`…/join ×2`** — 설계된 동작(TTS 능력 보고)이나 effect deps 에 `locale` 이 있어
   **로케일 변경마다 join 이 한 번 더** 간다. 앞 감사가 P3 로 남겼다.
3. **`/api/currency/rate ×2`** (관제) — 미판별, A8 후보로 남아 있다.
4. `buildRoomSnapshot` 은 8개를 `Promise.all` 로 읽은 뒤 **POI·사진을 순차로** 더 읽는다 [코드 실측].

## §E 하지 않을 것

- 고객 사이트(랜딩·투어상세·마이페이지) — 별도 트랙 존재
- 인프라 티어 변경(Vercel·Supabase) — 사장님 결정
- 세무·정산 **로직** 변경 — 성능 목적이어도 자율 수정 금지, 보고만
- 실기기 측정 — 사람 게이트. 스로틀은 **재현 가능한 대리값**이며 그 사실을 원장에 명시한다
- Tier1 LLM 실측 — 비용 발생, **사장님 승인 후**
