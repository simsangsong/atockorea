# 가이드 영상 표준 문법 v1 — 「만장굴 문법」 (2026-08-04 사장님 승인)

만장굴 v3.2 완성본(와이드 타이포 컷)을 보고 사장님이 확정: **"이 느낌을 표준 스크립트로.
다른 롱테이크 버전들도 중간중간 잘라서 이런 느낌으로."**
이 문서가 모든 명소 가이드 영상 스펙의 기준이다. 신규 스펙은 처음부터 이 문법으로 쓰고,
기존 3편(감천·용궁사·성산일출봉)은 **소스가 있는 PC 세션에서** 이 문법으로 재단한다(§6).

## §1 페이싱 — 속도는 넷뿐이다

| 속도 | 용도 | 규칙 |
|---|---|---|
| **1x** | 턴(회전)·stopLabel·시그니처 경관·콜드오픈·promise·recap | 전체의 **≤40%** (validate 게이트). 시그니처에 몰아준다 |
| **1.2x** | 응시·완만한 팬·강등된 1x 후보 | 팬 창과 겹치는 트랜짓의 기본값 |
| **1.5x** | 팬이 약하게 걸리는 트랜짓 | turns.mjs 창과 겹치면 2x 금지, 여기로 |
| **2x** | 팬 0건 직선 걷기 — **상한** | 비트당 화면 ≤5.2s (validate). 그 이상은 자르라(§2) |

🔴 **2x 초과 금지.** 구판의 4~8x 트랜짓이 "휙휙 돌아가는 빨리감기" 컴플레인의 원인이었다.
속도로 압축하지 말고 **잘라서** 압축한다.

## §2 중간 잘라내기(재단) — 롱테이크 압축의 표준 패턴

긴 걷기 구간은 고배속 대신 **슬라이스 + 디졸브**로 압축한다:

- 구간을 **2x 슬라이스 여러 개**(비트당 화면 ≤4.5s 권장)로 쪼개고 사이를 **0.8s 디졸브**로 잇는다.
- 첫 슬라이스의 `in`과 마지막 슬라이스의 `out`은 이웃 비트와의 접합 시각에 고정한다.
- 화면 시간이 디졸브(0.8s)보다 짧은 마이크로 슬라이스는 금지 — 그 구간은 통째로 2x 재생.
- 뒤에 held 비트(폴라로이드/freeze)가 붙는 비트는 `out`을 움직이지 마라 — held 의 `at`과 정합돼야 한다.

## §3 폴라로이드 — 「앵글 정지 + 피사체 전체」 (사장님 규칙 2026-08-04)

- 캡처 프레임은 **카메라가 멈추고 피사체 전체가 프레임에 들어온 순간**만. 팬 도중 캡처 금지.
- 판정은 눈으로 한다: 후보 프레임을 실제로 뽑아(turns.mjs 팬 창 **종료 이후**부터 탐색) 검수.
- **규칙에 맞는 프레임이 없으면 폴라로이드를 빼라**(만장굴 동굴 입구 사례 — 인파+블러로 삭제).
- 폴라로이드 `at` = 앞 비트 `out` = 뒤 비트 `in` (validate 게이트).

## §4 구조와 타이포

- **구조:** 콜드오픈 3비트(시그니처 2 + 진입 티저 1, mute) → promise → 진입 시퀀스(**실제 동선 순** —
  재촬영으로 타임스탬프가 뒤에 있어도 동선 위치로 배치) → 스톱들 → 반환점 → 복귀 → 주광 recap.
- **스톱 카드 캡션 = 실용 정보**: 요금·휴관일·온도·규모 수치. 클레임은 match_pois.content_locales 에서만,
  단위는 스펠아웃(metres, °C). ⚠ **clean 롤은 캡션을 렌더하지 않는다** — 화면에 태울 수치는 반드시
  stopLabel 비트에 실어라(만장굴 대성당 비트 사례).
- 화살표 금지(2026-08-01) — 정지 + 셸 타이포만. 챕터 간격 ≥10s.
- 걷는 컷은 상단 웨이파인딩(kicker)만 — 하우스 스타일.

## §5 워크플로 — 원커맨드

```bash
npm run video:guide                      # 전 스펙: turns → motioncut → validate → 드래프트 렌더
npm run video:guide -- <slug>            # 한 편만
npm run video:guide -- <slug> --check    # 실측·게이트만 (렌더 없음)
npm run video:guide -- <slug> --full     # 마스터(crf17) + 타이포 셸(vfull --wide)
```

`scripts/video-guide/run.mjs` 가 아래 순서를 그대로 실행하고, **선행 조건이 없으면 렌더 대신 멈춘다**
(소스 폴더/파일 부재 · 음악 베드 부재 · ffmpeg 부재 — 각각 고치는 법을 같이 찍는다).
게이트가 빨간 스펙은 렌더로 넘어가지 않는다.

### 단계 (수동으로 돌릴 때의 순서 — 위 커맨드가 이걸 감싼다)

1. 클립 전수 컨택트시트(6프레임/클립) — **파일명 말고 화면으로 식별**
2. 스펙 v1 (이 문서 §1~§4 준수)
3. `turns.mjs` 실측 → turn 비트를 실측 창에 정렬 (팬 0건 클립에 turn 금지)
4. `motioncut.mjs` → 경계 스냅
5. `validate.mjs` **0 FAIL**
6. `build.mjs --draft` → 사장님 프리뷰 → 컨펌
7. 풀 렌더(crf17) + `vfull.mjs --wide` (타이포 셸) → `-wide-review.mp4` 로 최종 확인
8. 음악: heedotrip 베드 풀에서 **본편보다 긴 곡 우선**(루프 이음매 회피). `assets/audio/video-guide/` 는
   gitignore — 렌더 머신에 mp3 복사 필요

## §6 기존 3편 재단 — 다음 PC 세션의 작업 지침 (스펙은 아직 건드리지 않았다)

대상: 감천(>2x 트랜짓 28개) · 용궁사(17개) · 성산일출봉(32개). 셋 다 4~8x 고배속 롱테이크 문법의 구판이다.
🔴 **원격 세션에서 눈감고 자르지 마라** — 이번 세션에서 등간격 슬라이스로 일괄 재단해 봤다가
사장님 지시로 되돌렸다. 슬라이스 위치는 반드시 **소스를 보면서** 정한다. 절차:

1. 대상 비트 추출: 스펙에서 `kind=clip && speed>2` 를 전부 나열(위 개수의 근거).
2. 비트마다 화면 시간 t 를 보존하는 재단을 §2 패턴으로: 소스 범위에서 **컨택트시트/프레임을 열어**
   좋은 순간들로 2x 슬라이스(비트당 화면 ≤4.5s)를 고르고 0.8s 디졸브로 잇는다.
   첫/끝 슬라이스는 이웃 접합 시각에 고정. held 비트(폴라로이드/freeze) 앞 `out` 은 움직이지 않는다.
3. 화면 시간이 0.8s 디졸브보다 짧아지는 마이크로 슬라이스 금지 — 그 구간은 통째로 2x.
4. 폴라로이드 전수 §3 검수(세 편 다 구판 타이밍 그대로다 — 팬 도중 캡처가 섞여 있을 수 있다).
5. motioncut 재실행(신규 무전환 경계) → validate 0 FAIL → 드래프트 → 사장님 컨펌 → 풀 렌더 + vfull --wide.

러닝타임은 화면 시간 보존이면 구판과 동일하게 유지된다(감천 ~237s · 용궁사 ~224s · 성산 ~265s).
