### A-1 `html-video` 실체 (웹 확인, 추측 아님)

`nexu-io/html-video`, Apache-2.0, per-render 과금 없음. Open Design 팀 공식 프로젝트.

```
source fetch → agent loop → content-graph(다중 프레임 IR)
             → 프레임별 자립 애니메이션 HTML → Hyperframes 렌더 → ffmpeg 인코드
```

- **Hyperframes 엔진 = 헤드리스 Chromium이 애니메이션 HTML을 프레임 단위로 녹화 → ffmpeg(libx264)**
- 템플릿 21종, 각 `template.html-video.yaml` 매니페스트(입출력·라이선스 명시)
- Node 20+ · pnpm 9+ · ffmpeg · Playwright Chromium
- CLI / 스튜디오 UI(`127.0.0.1:3071`) / 에이전트 스킬(Claude Code 포함 14종)
- 🔴 **자막·캡션 문서 없음** · 🔴 **로케일 처리 문서 없음**
- Remotion·Motion Canvas·Revideo는 **로드맵**이고 지금 도는 건 Hyperframes뿐

🔴 **핵심**: Hyperframes의 구조는 **오늘 우리가 완성한 것과 같다** — Playwright로 애니메이션
HTML을 프레임 캡처해서 ffmpeg로 굽는다. `scene.mjs` + `vfull.mjs`가 정확히 그것이다.

## §C 사장님 요구와 기존 설계의 차이 — 딱 한 군데

| | 기존 설계 | 사장님 요구 |
|---|---|---|
| 화면 문구 | **없음**(순수 픽토그램) | **영어 자막 번트인** |
| 로케일 | WebVTT 10종, 앱이 선택 | 번트인 영어 **아래에** 로케일 자막 오버레이 |

두 안은 충돌하지 않는다 — **오늘 관광지 영상에서 확정한 존 계약(V6-D3)과 같은 구조**다:
프레임에 영어를 굽고, 하단 한 줄은 앱이 채우도록 비워둔다.

🔴 **다만 함정이 하나 있다.** 브라우저 네이티브 `<track>` 자막은 기본적으로 **하단 중앙**에
그려진다. 영어를 아무 데나 구우면 VTT 자막과 겹친다. 그래서 기존 HTML이 "하단 420px 안전지대"를
비워둔 것이고, **그 420px가 곧 로케일 존**이 된다. 영어는 그 **위**에 굽는다.

## §D `html-video`를 쓸 것인가 — 안 쓴다 (단, 두 가지는 훔친다)

**쓰지 않는 이유** (호불호가 아니라 실측 근거):

1. 엔진이 우리 것과 **같은 구조**다. 얻는 게 능력이 아니라 의존성이다 — pnpm + 6패키지 모노레포 + 스튜디오 서버.
2. 🔴 **자막과 로케일이 문서에 없다.** 이 트랙에서 제일 어려운 두 가지가 정확히 거기서 비어 있다.
3. 우리는 이 부류 렌더러가 밟는 지뢰의 **해답을 이미 갖고 있다** — 프레임당 스크린샷 비용(T-17),
   오버레이 유지 방식 4종 중 1종만 동작(T-32), 무에러 합성 실패(T-35), 폰트 무언 대체(T-18).
   처음 쓰는 엔진에서 이걸 다시 겪는다.
4. Remotion은 아직 로드맵이다. 참고 영상 1번이 권한 게 Remotion인데 그건 아직 안 돈다.

**훔칠 것 2가지:**
- **템플릿 매니페스트** — 템플릿마다 입력·출력·라이선스를 YAML로 선언하는 방식. 우리 스펙 JSON에 그대로 이식.
- **PAGE → MOTION RECIPE → RENDER 3단 분리** — 내용(무엇을 말하나)과 모션(어떻게 움직이나)을
  분리해서, 모션을 이름으로 지정한다. 이게 "elements에 애니메이션 입힌다"의 엔지니어링 형태다.

**스파이크는 한다(반나절):** 21개 템플릿을 **모션 레퍼런스로만** 본다. 코드를 들이지는 않는다.

## §E 권고 아키텍처 — "관광지 파이프라인에서 실사 레이어를 뺀 것"

```
scene-spec JSON  ──▶  씬 HTML(애니메이션)  ──▶  Playwright 프레임 캡처
                                          ──▶  tpad 홀드 ──▶ ffmpeg 인코드
                                          ──▶  cues.json + WebVTT ×10
```

관광지 파이프라인에서 **그대로 재사용**: `lib/deps.mjs`(의존성 리졸버) · Playwright 진입
애니메이션 + `tpad=stop_mode=clone` 홀드 · 셸 존재 픽셀 검사 · `__measure` 적합 게이트 ·
가독 시간 예산 · 검토용 사본 자동 생성 · `exportmeta` 큐 트랙.
**빼는 것**: 실사 마스터 리프트, 배속 문법, 화살표, 클로즈업, 컬러 그레이딩.
**더하는 것**: 모션 어휘(§E-2), 자막 이원화(§E-3).

### E-1 두 영상 계열, 엔진 하나

| 계열 | 길이 | 종횡비 | 재생 위치 |
|---|---|---|---|
| 아침 출발 안전 안내 | 30–45s | 세로 | 앱 모닝 브리핑 카드 (기존 `SafetyVideoCard`) |
| 앱 기능 안내 | 20–40s ×N | 세로 | 앱 온보딩/기능 진입점 |

### E-2 모션 어휘 (이름으로 지정하는 레시피)

참고 영상 4번의 페이지별 모션 지정을 우리 식으로. 초안 6종 —
`card-in`(카드 아래에서 진입) · `list-reveal`(항목 순차 등장) · `device-push`(기기 프레임 밀어넣기) ·
`highlight-ring`(요소 강조 링) · `count-up`(숫자 카운트) · `split-compare`(전/후 대비).
CSS/WAAPI 한 벌로 공유하고 씬 스펙에서 `motion: "list-reveal"`로 부른다.

### E-3 자막 이원화 (이 트랙의 본체)

- **영어**: 프레임 상단~중단에 번트인. 유튜브·OTA에서 자체 완결.
- **로케일 10종**: 하단 420px 존. 앱은 기존 `<track>` 경로 유지(글자 크기 설정도 따라감).
- **게이트 3종**: ① 영어 텍스트가 하단 존을 침범하면 FAIL ② 가독 시간 ≥ max(2.8s, 글자/12)
  ③ CJK 글자 단위 줄바꿈 0 (저장소 CJK 불변 규칙의 영상판).

**내가 결정함** (재론 없이 진행): html-video 미도입 · 엔진은 관광지 파이프라인 재사용 ·

🔴 **사장님만 알 수 있는 것 2가지:**
1. **앱 기능 안내를 어느 기능부터** 만들 것인가 — 기능 목록과 우선순위는 콘텐츠 판단이다.
2. **넉 달 멈춘 `pending_review` 안전 영상** — 검수를 안 한 것인지, 보고 반려한 것인지.
   반려였다면 그 이유가 E5의 출발점이다.

**그 외 게이트 1건:** 음악 베드. 관광지 영상과 같은 문제 — 상업 이용 가능 음원이 필요하다.
안전 안내는 무음이어도 성립하므로 E5는 음악 없이 진행 가능하다.
