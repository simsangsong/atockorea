# 카드/모션 안내 영상 — 설계와 실행 플랜 (v2)

작성 2026-07-30 · **v2 개정 같은 날.** v1은 기존 픽토그램 자산(`safety-intro-30s.html`)을
재사용하자고 했는데 **사장님이 그 노선을 반려**했다("픽토그램으로 조잡한 그림따위를 이어붙이는
게 아닌"). 목표는 참고 영상 수준의 **카드·모션 데크**다. v1의 조사 결과(기존 자산 목록,
멈춘 검수, VTT 충돌 함정)는 유효하고, **시각 노선만 폐기**한다.

> 결론: **엔진은 이미 있다. 없는 건 디자인 시스템이다.** 우리 렌더러는 HTML/CSS가 그릴 수
> 있는 것은 전부 그린다 — 오늘 관광지 영상에서 검증했다. 그러니 이 트랙의 실제 작업은
> 렌더러가 아니라 **① 측정된 디자인 시스템 ② 카드에 넣을 진짜 스크린샷 ③ 자막 이원화**다.

## §A 목표 수준 — 무엇이 그 영상을 좋아 보이게 하나 (실측)

참고 화면녹화에서 라이트 데크 프레임을 2배 확대해 측정했다. 값은 재본 것이다.

### A-1 라이트 데크 (목표 스타일)

| 요소 | 실측 |
|---|---|
| 배경 | 따뜻한 크림 `#f0ece5` 계열이 화면의 **61%** — 순백도 회색도 아니다 |
| 카드 면 | 순백 `#ffffff`, 화면의 **11%** |
| 잉크 | 거의 검정 `#101010`, 화면의 **4%뿐** |
| 액센트 | 앰버/탄 — **활성 카드 테두리와 그 서브라벨에만** |
| 타입 레지스터 | **딱 2개** — 헤드라인(굵은 CJK 디스플레이, 좌정렬 2줄) + 크롬(모노 대문자, 넓은 자간, 저대비) |
| 카드 구조 | 위 60% = **실제 화면 스크린샷**, 아래 40% = 흰 라벨판(굵은 제목 + 회색 부제) |
| 활성 상태 | 앰버 테두리 + 부제 앰버 + 살짝 들림 |
| 네 귀퉁이 크롬 | `REC · AI VIDEO · 2026`(좌상) `PAGE 03 · SHOT MAPPING`(우상) `PAGE → MOTION RECIPE → REMOTION VIDEO`(좌하) |
| 여백 | 카드 행이 화면 **중간 1/3**만 차지. 위아래가 비어 있다 |

### A-2 다크 데크 (같은 시스템의 반전)

따뜻한 블랙 `#181510` 계열 · 모노 대문자 타이틀(`SKILL 01 · HyperFrames`) · 그 아래 굵은
CJK 한 줄 · **거대한 유령 숫자**(우상단, 배경보다 살짝 밝은 정도) · 앰버 세그먼트가 들어간
얇은 **진행 바** · 하단 중앙 자막 한 줄.

### A-3 🔴 완성도의 정체 — 더하는 게 아니라 빼는 것

여섯 가지가 전부다. 전부 우리가 오늘 이미 쓴 기법이다.

1. **액센트 1색.** 활성 상태에만. 두 번째 색을 쓰는 순간 무너진다.
2. **타입 레지스터 2개.** 디스플레이 + 모노 크롬. 세 번째 서체는 없다.
3. **카드 안은 진짜 내용.** 아이콘이 아니라 **실제 화면 캡처**. 이게 "슬라이드"와 "시스템 리드아웃"을 가른다.
4. **네 귀퉁이 크롬 마이크로 라벨.** 구현 비용 거의 0, 효과 최대. "이건 시스템이 뽑은 화면"이라는 인상 전부가 여기서 온다.
5. **모션에 이유가 있다.** 카드가 하나씩 늘어나는 건 설명이 하나씩 늘기 때문이다(실측: 1장 → 3장 → 5장). 장식 모션은 없다.
6. **글자가 실제로 크다.** 헤드라인이 프레임 높이의 1/8.

🔴 **픽토그램이 조잡해 보였던 이유는 그림 실력이 아니라 이 여섯 개가 없어서다.**

## §C 아키텍처 — 관광지 파이프라인에서 실사를 빼고 스크린샷을 넣는다

```
scene-spec JSON
   ├─ (신규) 스크린샷 스테이지: Playwright로 우리 앱을 실제로 몰아 UI 캡처
   ├─ 씬 HTML(카드·모션) ── Playwright 프레임 캡처 ── tpad 홀드 ── ffmpeg
   └─ cues.json + WebVTT ×10
```

**그대로 재사용**: `lib/deps.mjs` · 진입 애니메이션 + `tpad=stop_mode=clone` 홀드 ·
셸 존재 픽셀 검사 · `__measure` 적합 게이트 · 가독 시간 예산 · 검토본 자동 생성 · 큐 트랙.
**빼는 것**: 실사 마스터 리프트 · 배속 문법 · 화살표 · 클로즈업 · 컬러 그레이딩.

🔴 **새로 만드는 것 중 제일 값어치 있는 건 스크린샷 스테이지다.** 앱 기능 안내 카드에 들어갈
그림은 **우리 앱의 실제 화면**이고, 우리는 Playwright로 우리 앱을 몰 수 있다. 아이콘을 그리는
대신 진짜를 찍는다 — §A-3의 3번을 공짜로 만족시킨다. 캡처는 스펙에 URL·뷰포트·대기 조건·
마스킹(개인정보) 규칙으로 선언한다.

### C-1 종횡비 — 세로가 주, 16:9는 파생

앱 재생이 목적이므로 **1080×1920 세로가 주**(관광지 트랙 V6-D1과 일관). 다만 참고 데크는
16:9라 **카드 4장 가로 배열이 세로에서 성립하지 않는다** — 세로에서는 **2×2 그리드** 또는
**세로 스택 3장**으로 바꾼다. 16:9 변형은 같은 스펙에서 파생(관광지 `--wide`와 같은 방식).

## §D 씬 어휘 — 이름으로 부르는 카드/모션 레시피

스펙에 `scene: "card-grid"`, `motion: "stagger-in"` 형태로 쓴다.

| 씬 | 쓰임 | 모션 |
|---|---|---|
| `title-card` | 챕터 진입 | 유령 숫자 페이드 + 모노 타이틀 자간 수축 + 진행바 세그먼트 전진 |
| `card-grid` | 기능 2~4개 나열 | 카드 순차 등장(stagger 130ms), 활성 카드로 앰버 이동 |
| `screen-focus` | 화면 하나 집중 | 스크린샷 푸시인 + 강조 링 + 콜아웃 라인 |
| `step-list` | 절차 3~5단계 | 항목 순차 등장 + 완료 체크 |
| `compare` | 전/후 | 세로 분할 와이프 |
| `stat` | 숫자 강조 | 카운트업 + 단위 페이드 |
| `outro` | 마무리 | 로고 + 브랜드 라인 |

각 씬은 `template.yaml`로 입력·출력을 선언한다(html-video 매니페스트 아이디어 차용).
