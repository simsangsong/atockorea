# 손님 대시보드가 「언어를 바꾸면」 사라지는 문제 — 감사 + 수정 (2026-08-07)

**v2 — 사장님 지시 반영.** v1 은 "어드민 미리보기를 지속시키자"였고, 사장님이 더 나은 규칙을 주셨다:
*"role이 서로 전환되고 오염되는건 아예 차단해야하는거 아니야? 나가기나 미리보기나 이런게 왜 필요해?"*
→ **역할 전환 자체를 막는다.** v1 이 필요하다고 적었던 「나가기·미리보기 모드」는 **불필요한 것으로 확인**돼 전부 삭제했다(§7).

사장님 보고: *"손님 대시보드가 영어에서는 안 사라지는데 다른 언어 선택만 하면 또 사라져버려.
거기에 추가로 고객 대화언어 선택 옵션도 없어지고 앱언어 선택만 남아."*

---

## §0 한 줄 결론

**언어 선택은 원인이 아니라 방아쇠다.**
언어를 바꾸면 클라이언트가 `/join` 을 **다시** 부르는데, 최초 진입에만 있던 `?rt=` 토큰은 이미
URL 에서 지워진 뒤라 **서버가 "누가 들어왔는가"를 처음부터 다시 판정**한다. 토큰이 없으므로
**어드민 쿠키가 이긴다** → 역할이 `customer` → `admin` 으로 바뀐다.

**UI 결함이 아니라 인증 결함이다. 대시보드는 숨겨진 게 아니라 손님이 아니게 된 것이다.**

## §1 스크린샷 한 장이 답을 다 들고 있었다 (증거 4개)

| 화면에서 본 것 | 코드 조건 | 함의 |
|---|---|---|
| 홈 탭이 탭바에 **없음**(4개) | `RoomShell.tsx:805` `(home ? HOME_TABS : BASE_TABS)`, `home` 은 `TourRoomClient.tsx:1258` 에서 `viewerRole === 'customer'` 일 때만 | viewerRole ≠ customer |
| 빈 채팅 문구가 **스태프용** | `ChatFeed.tsx:673` `isOperatorViewer` = guide·driver·**admin** | guide·driver·admin 중 하나 |
| 퀵 리플라이는 **손님용** | `quickReplies.ts:480` — guide/driver 만 분기, 나머지는 customer 폴백 | guide 도 driver 도 아님 |
| **채팅언어 셀렉터 소실**(사장님 추가 보고) | `TourRoomClient.tsx:1322` `onChatLocaleChange` 는 customer 일 때만 전달 → `SettingsTab.tsx:468` 이 섹션 전체를 `&&` 로 감쌈 | viewerRole ≠ customer |

네 줄이 교차하는 값은 **`admin` 하나뿐**이다.
🔴 **그래서 이건 기능 4개가 각각 고장난 게 아니라, 역할 하나가 무너진 것이다.**

## §2 근원 — 서버 권한 판정의 우선순위 (실측)

`lib/tour-room/access.ts` `resolveRoomActor()` 는 **요청마다** 신원을 다시 판정했고, 순서가
`① 토큰 > ② 어드민 > ③ 룸 세션 > …` 이었다.

같은 파일의 모듈 독이 ①이 ②보다 위인 이유를 **정확히 이 시나리오로** 적어 두었다 —
*"…otherwise a logged-in admin can never preview the guest experience (**the home dashboard**…)"*.
**의도는 맞았고 구현이 반쪽이었다.** 그 강등은 **토큰이 요청에 들어 있는 동안에만** 살았는데,
클라이언트는 첫 join 직후 `scrubTokenFromUrl()` 로 `?rt=` 를 지우고 **다시 실어 보내는 곳이 없다.**

### 실측 (jest 프로브, 대조군 포함)

동일한 **customer 룸 세션**을 넣고 어드민 쿠키만 대조군으로 바꿨다:

```
쿠키 없음 → {"kind":"session","role":"customer"}   ✅
쿠키 있음 → {"kind":"admin",  "role":"admin"}      🔴
```

**게이트가 자기가 방금 서명해 발급한 「이 기기는 customer」를 어드민 쿠키로 덮어썼다.**

### 「영어는 왜 멀쩡한가」

영어가 특별한 게 아니라 **바꾸지 않은 상태**가 특별하다. `changeLocale` 은 `next === locale` 이면
조기 반환한다 → join 이 안 일어나고 역할도 안 바뀐다. **바꾸는 순간 무조건 터진다.**
✅ **사장님 확인:** 다시 영어로 되돌려도 안 돌아온다 — 또 한 번의 무토큰 join 이므로. 예측대로였다.

### 같은 구멍을 밟던 호출 4곳

| 위치 | 호출 | 토큰 |
|---|---|---|
| `TourRoomClient.tsx:338` | 마운트 join | **있음** ✅ |
| `:302` | 앱 언어 변경 | 없음 🔴 |
| `:318` | 채팅 언어 변경 | 없음 🔴 |
| `:1019` | TTS 능력 보고(`capabilityOnly`) | 없음 🔴 |

🔴 **네 번째가 가장 조용하다.** 룸을 열 때마다 자동으로 돌고 응답을 `.catch(() => undefined)` 로 버린다.
그래서 **언어를 안 건드려도** 참가자 행이 이미 오염된다.

## §4 대시보드가 "사라지는" 실제 경로

```
viewerRole = 'admin'
  → home prop = undefined              → 탭바가 4개로 렌더        (홈 탭 소실)
  → onChatLocaleChange 미전달           → 채팅언어 섹션 통째로 소실
  → companionInvite 미전달              → 동행 초대 카드 소실
  → RoomShell 재마운트 시 tab='chat'    → 스태프용 빈 채팅 문구
```

마지막 줄이 **스크린샷이 왜 하필 채팅 탭인지**까지 설명한다 — 사장님은 **설정 탭**에서 언어를
바꿨는데 화면은 **채팅**에 있었다. 룸이 통째로 재마운트됐기 때문이다(§5-b).

## §5 원인은 하나, 증상은 넷

- **(a) 🔴 P1** — 어드민 쿠키가 룸 세션을 덮어썼다. *(본건)*
- **(b) ⚠ P2** — 언어를 바꾸면 룸이 통째로 언마운트됐다. `doJoin` 이 재조인에도
  `status:'joining'` 을 때리고 `TourRoomClient:374` 가 전체화면 스켈레톤을 반환.
  **어드민이 아닌 진짜 손님도** 화면이 깜빡이고 보던 탭에서 튕겼다.
  🔴 PR #739(I7v4)와 **같은 모양** — 상태가 조용히 언마운트되는 곳에 살았고, 왕복을 잰 테스트가 없었다.
- **(c) ⚠ P2** — join 이 참가자 행의 `role`·`display_name` 을 무조건 덮어썼다.
- **(d) ⚠ P3** — `TourModeEntry.tsx:69/122/163` 은 `?rt=` 없이 룸으로 보낸다.

## §7 수정 — 구현 완료

사장님 규칙: **한 방 안에서 한 기기의 역할은 입장할 때 한 번 정해지고, 명시적 토큰으로만 바뀐다.**

### ① 서버 판정 — 룸 세션이 어드민 쿠키보다 우선 (`lib/tour-room/access.ts`)

`① 토큰 > ② 룸 세션 > ③ 어드민 > ④ 소유자 > ⑤ 머천트 가이드 > ⑥ 손님 이메일`

**승격 불가:** 룸 세션은 이 게이트가 직접 서명해 발급하고, 발급 시점에 이미 전체 사다리를 통과했다.
따라서 **세션에 적힌 역할 이상은 절대 못 준다** — 어드민에게는 강등만, 비어드민에게는 변화 없음.

**관제는 잃는 게 없다(실측):** 어드민 화면은 룸 API 를 **어드민 쿠키만으로** 부르고
`x-tour-room-auth` 를 **안 보낸다**(`components/tour-ops/OpsRoomDrawer.tsx:74`). 이 분기가 아예 안 탄다.
→ **그래서 v1 이 필요하다던 「나가기·미리보기」 탈출구가 불필요하다. 사장님 지적이 맞았다.**

### ② 좌석 고정 — `pinnedParticipantRole()` (신규, `access.ts`)

```
토큰 조인   → 토큰의 역할. 좌석을 바꾸는 유일한 길이고, 이건 사람의 명시적 행위다.
그 외 전부  → {기존 행, 이번 요청} 중 권한이 더 낮은 쪽.
```

🔴 **최솟값을 취하는 게 핵심이다.** 안 그러면 「고정」이 반대 방향의 구멍이 된다 —
낡은 `admin` 행이 손님 자격을 들어올리는 승격. 최솟값은 **양방향 모두** 접는다.

`join/route.ts` 는 이제 upsert·세션 서명·리드 판정에 **같은 `role`** 을 쓴다(셋이 어긋나면 다음
요청이 다시 벌어진다).

### ③ 재조인이 룸을 무너뜨리지 않게 (`hooks/useTourRoomSession.ts`)

`setState((prev) => prev.status === 'joined' ? prev : { status: 'joining' })`.
첫 조인만 보여줄 게 없다. 재조인은 마지막 룸을 화면에 둔 채 데이터만 갈아끼운다. 실패 동작은 무변경.

### ④ 상설 게이트 (전부 신규, **뮤테이션 검증 완료**)

| 파일 | 잠그는 것 |
|---|---|
| `__tests__/lib/tour-room/access.test.ts` §「the seat survives the token being gone」 | **토큰이 사라진 다음 요청** — 헤더형·`rs` 쿼리형·타 예약 세션·위조 세션 |
| 같은 파일 §「pinnedParticipantRole」 | 강등만 되고 **승격은 안 됨**, 토큰만이 좌석을 바꿈 |
| `__tests__/api/tour-rooms-join.test.ts` §「the seat is pinned」 | 라우트에서 **행·세션·응답 셋이 동시에** customer 로 남는지 |
| `__tests__/hooks/useTourRoomSession.test.tsx` | 언어 전환이 **스켈레톤을 통과하지 않음**(왕복) |

기준선: **tsc 0** · 대상 스위트 **156 suites / 1,731 tests 전부 green**.
뮤테이션 확인: ③을 되돌리면 「스켈레톤을 통과하지 않음」 케이스가 **즉시 실패**한다.

### ⑤ 하지 않은 것 (의도적)

- **클라이언트 토큰 재전송** — v1 플랜의 Phase 2. ①로 세션이 신원이 되면서 **불필요**해졌다.
  §5(d) 엔트리 리스트 경로도 저장된 세션이 신원이므로 **같이 닫힌다.**
- **DB 일괄 정리** — admin 행 9개 중 **정당한 것도 섞여 있다**(관제가 방을 연 기록).
  구분할 근거가 없으므로 건드리지 않는다. 복구는 §8.

## §8 🔴 사장님이 지금 해야 할 일 — 개인 링크 한 번 클릭

배포해도 **사장님 기기는 그대로 어드민입니다.** 저장된 세션도 참가자 행도 이미 `admin` 이라
고정 규칙이 그 값을 지킵니다(설계대로 — 이게 승격 방지의 대가입니다).

**`?rt=` 개인 링크로 룸을 한 번 열면** 토큰 경로가 좌석·표시이름·세션을 전부 손님으로 돌려놓고,
그 뒤로는 언어를 몇 번 바꾸든 유지됩니다. **한 번이면 영구 복구입니다.**

## §9 남은 일 — 실렌더 검증 (다음 세션 첫 일감)

⚠ **아직 브라우저로 왕복을 못 돌렸다.** 서버 계층은 실측했지만 화면은 아직 안 봤다 —
이 레포의 반복된 교훈([[feedback_real_render_beats_source_review]])대로 **여기서 끝내면 안 된다.**

1. `?rt=` 개인 링크 진입 → 홈 대시보드 확인
2. 설정 → **일본어** → ① 홈 탭 유지 ② 타일 5종 ③ **채팅언어 셀렉터 유지** ④ 설정 탭에 그대로 서 있는가
3. **en → ja → ko → en** 왕복
4. 대조군: 시크릿 창(어드민 쿠키 없음)에서 같은 조작
5. DB 재확인 — 해당 device_key 행이 `customer` 로 남아 있는가

⚠ **워크트리는 HMR 이 안 먹는다 — dev 재시작 후 검증할 것.**
