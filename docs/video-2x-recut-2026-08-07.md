## 두 종류의 일이다 — 섞지 말 것

**① 늦추기만 하면 되는 것** (`slow-to-2x.mjs`)
`길이/2 ≤ 5.2s` 면 통째로 2x 로 재생하면 끝이다. 버리는 프레임 없고 `in`/`out` 도 안 움직이니
held 폴라로이드 정합도 유지된다. **판단이 필요 없다.** 이미 28비트 처리했고, 남은 40개는
전부 이 조건에 안 맞는 것들이다.

**② 컨택트시트를 봐야 하는 것** (`recut-<slug>-2x.mjs`)
화면 시간을 유지하면서 2x 로 내리려면 **소스의 절반 이상을 버려야** 한다. 뭘 버릴지는
눈으로 골라야 한다.

🔴 **기계적 등간격 재단은 이미 한 번 반려당했다**(§6). 주상절리 v2 반려 사유가 그것이고,
반려 목록에 「측정된 회전 4곳을 버렸다」가 적혀 있다.

```bash

#      - 각 프레임의 타임스탬프 + 회전 안이면 🔴 TURN

# 2) 시트를 눈으로 보고 「지루한 구간」을 고른다
# 3) recut-<slug>-2x.mjs 의 RECUT 표에 슬라이스와 **그 시트가 무엇을 보여줬는지** 적는다
# 4) node scripts/video-guide/recut-<slug>-2x.mjs --dry-run   → 화면 시간이 보존되는지 확인
# 5) --dry-run 빼고 실행 → node scripts/video-guide/validate.mjs docs/video-specs/<slug>.json
```

## 이 두 스펙에서 실제로 배운 것

- **회전은 대개 알아서 지켜진다.** 여섯 비트 전부 회전 창이 `in` 에서 끝나고 `out` 에서
  시작했다 — 비트 자체가 회전 경계에서 잘려 있기 때문이다. §2 의 「첫 `in`·마지막 `out` 고정」
  규칙이 그래서 회전을 자동으로 보호한다. **그래도 매번 시트의 TURN 표시를 확인하라.**
- **볼거리는 비트의 한쪽 끝에 몰려 있고 반대쪽은 사람 뒷통수다.** 주상절리 여섯 비트가
  전부 그 모양이었다. 그래서 버리는 건 거의 항상 「전이 구간」이다.
- 🔴 **가운데를 반으로 자르면 안 되는 경우가 있다.** 비트 41 은 지루한 구간이 **양쪽**에
  있고 그 사이(84.5)에 해안 암반 뷰가 있었다. 한 번에 가운데를 버렸으면 그 뷰가 날아갔고,
  그게 정확히 v2 반려 사유다. → **슬라이스 3개**로 갈랐다.
- **마이크로 슬라이스 금지가 실제로 걸린다.** 계산상 딱 맞는 분할이 두 번째 슬라이스를
  0.6s 화면으로 만들어 §2 위반이 됐다. 0.8s 디졸브보다 짧으면 안 되니 앞 슬라이스에서
  덜어 왔다.
