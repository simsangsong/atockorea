## A. 융합 명제

**두 조각이 이미 다 있다. 서로 못 만나고 있을 뿐이다.**

현재 앱은 재질·토큰·스킨·대비 게이트·POI 자산이 완성 단계다. 제로베이스 설계가 가진 것은 **정보 계층 하나** — 숫자를 문장에서 꺼내 화면의 주인공으로 만들고, 사진을 주인공 자리에 앉히는 방식.

따라서 이 융합은 **색·그림자·재질을 단 하나도 바꾸지 않는다.** 바뀌는 것은 타입 스케일 한 단, 행 순서, 그리고 이미 있는 자산의 배치 위치뿐이다.

## C. Part A — 숫자 우선 계층 (N0, 자산 의존 0)

이 융합의 핵심이자 가장 싼 부분. **사진도, 새 자산도, 새 토큰도 필요 없다.**

### C-1. 타입 스케일에 한 단 추가

```css
/* 카운트다운/시각의 단 — tr-display(20)보다 위. hero 카드 안에서만. */
.tr-numeral {
  font-size: calc(34px * var(--tr-font-scale, 1));
  line-height: 1.05;
  font-variant-numeric: tabular-nums;
}
:where(.tr-numeral) {
  font-weight: 700;
}
```

- **34px 근거:** `tr-display` 20 대비 1.7배. 팔 길이에서 흔들리는 차 안에서 읽는 거리.
- `--tr-font-scale`을 곱해 사용자 글자 크기 설정을 따른다 (B3).
- `:where()`로 weight를 걸어 call-site 유틸이 이기게 한다 (B4 규율 준수).
- **`.tr-card-hero` 안에서만 허용.** B9의 "주인공은 하나" 규칙이 숫자에도 그대로 적용된다. 큰 숫자가 둘이면 둘 다 안 크다.

### C-2. NowCard 4행 문법

지금은 `title` 하나가 시간과 장소를 동시에 진다(B5). 그래서 문장이 길고 숫자가 묻힌다. 행마다 역할을 하나씩만 준다.

```
eyebrow    자유시간                        무슨 일이      tr-meta
NUMERAL    18:41                          얼마나 남았나   tr-numeral   ← 신규
title      파란 대문에서 만나요              어디로         tr-title
sub        당신 위치에서 6분 · 10:09 출발     뭘 하나        tr-card-text
action     지도 열기                                      tr-btn-physical (무변경)
chips      화장실 · 다음 스팟                              tr-chip-tap (무변경)
```

**상태 / 시간 / 장소 / 행동.** 부수 효과로 title이 짧아져 CJK 줄바꿈 사고 표면도 줄어든다.

### C-3. 상태별로 그 숫자가 무엇인가

| 상태 | 숫자 | 형식 | 틱 | 톤 |
|---|---|---|---|---|
| `free_time` | 남은 시간 | `18:41` 감소 | 1초 | base → T-5부터 warn |
| `rally_overdue` | 초과 시간 | `+04:12` 증가 | 1초 | danger |
| `moving` | 도착까지 | `7분` | 30초 | base |
| `arrived` | 체류 잔여 | `40분` | 30초 | base |
| `pickup_window` | 도착까지 | `4분` | 30초 | accent |
| `lobby` | D-N | `D-3` | 없음 | base |
| `ended` | — | 행 자체를 렌더하지 않음 | — | base |

**숫자가 없는 상태에서 그 행은 사라진다.** 억지로 채우면 계층이 죽는다.

### C-4. "시계"는 두 개가 섞여 있다

사장님 표현("시계가 큼지막하게")에는 **현재 시각**과 **카운트다운**이 같이 들어 있다. 같은 크기로 두면 위계가 없어진다.

- **카운트다운 = 주인공.** `tr-numeral`, hero 카드 안.
- **현재 시각 = 헤더 우측.** `tr-num tr-label` 12px. 손님이 상태바 대신 앱에서 시각을 확인하는 용도로만.

### C-5. 이 단계에서 재질이 바뀌지 않는 이유

| 요소 | 처리 |
|---|---|
| 색 | `TONE_INK`/`TONE_CLASS` 그대로. 숫자는 `--tr-ink` (B8) |
| 배경·그림자 | `.tr-card-hero` 그대로 (B9) |
| 버튼 | `tr-btn-physical` 그대로 |
| 칩 | `tr-chip-tap--quiet` 그대로 |
| 신규 토큰 | **0개** |

### C-6. 게이트 4가지

1. **font-scale 최대치.** 34 × 1.3 = 44px. 최장 문자열은 `+04:12`(6자). 최소 폭 기기에서 두 줄로 안 넘어가는지 **실기기 확인**.
2. **contrast 스킨.** 새 색이 없어 `skinContrast`는 자동 통과. 다만 700 weight가 그 스킨에서 과한지는 눈으로 봐야 한다 (B10 문맥).
3. **틱 비용.** 1초 리렌더는 `free_time`·`rally_overdue` 두 상태만. 나머지는 30초. `DepartureCountdown`의 기존 패턴(B14)을 그대로 따르고 두 번째 복사본을 만들지 않는다.
4. **CJK.** title이 짧아져 오히려 안전해지지만 `text-cjk-safe` 유지.

## D. Part B — 사진 융합 (N1~N2, 자산 의존 있음)

**C(숫자 계층)가 선다음에 얹는다.** 순서를 뒤집으면 사진이 주인공을 뺏는다.

### D-1. 5원칙

1. **사진 위에 글자를 얹지 않는다.** `skinContrast` 게이트가 재는 것은 토큰 쌍이고, 사진 밝기는 무한 변수라 게이트가 원리적으로 못 잡는다. 사진은 상단 밴드, 글자는 카드 표면 — B11이 이미 쓰는 문법이고, 그걸 홈으로 올리면 **검증된 대비 쌍이 하나도 안 깨진다.**
2. **사진은 카드 재질에 종속된다.** `--tr-rim`·`--tr-elev-2`·`--tr-radius-card`·accent hairline 전부 유지. 사진은 안쪽 상단 밴드이고 위 모서리만 카드 radius를 물려받는다. 신규 토큰 0개.
3. **주인공은 여전히 한 장.** 사진 카드가 hero면 `home-status-live`는 hero 클래스를 내려놓는다.
4. **`contrast` 스킨에서는 사진이 물러난다.** 그 스킨은 이미 shadow를 전부 죽인다(B10). 같은 논리로 밴드 높이를 절반으로 줄이거나 스와치로 대체.
5. **사진이 없으면 정확히 오늘 화면으로 돌아간다.** B11의 스와치 폴백을 **그대로 재사용**. 폴백 언어가 두 벌이면 그게 이 레포가 반복해 겪은 "두 번째 복사본"이다.

추가 규율: **홈 히어로와 채팅 카드는 같은 `SpotArrivalContent` 계약을 읽되 렌더만 다르다.** 채팅은 손대지 않고 데이터 복사본도 안 생긴다.

### D-2. 상태별 사진 소스

| 상태 | 사진 | 자산 |
|---|---|---|
| `moving` | 다음 스팟 POI 이미지 | 있음 |
| `arrived` | 현재 스팟 이미지 | 있음 |
| `free_time` | **집합 장소 사진** | **부재 (B12)** |
| `rally_overdue` | 집합 장소 사진 | **부재 (B12)** |
| `pickup_window` | 차량 사진 | 미확인 (§G) |
| `lobby` | 투어 히어로 이미지 | 있음(추정) |
| `ended` | 오늘 사진 1장 | 앨범 부재 |

### D-3. 진짜 병목은 UI가 아니라 자산 하나

**집합 장소 실사진.** 자유시간·rally 두 상태를 다 먹고, 손님이 실제로 못 푸는 문제("저기가 어디지")를 유일하게 푸는 사진이다. POI 사진으로 대체하면 예쁘기만 하고 아무것도 안 푼다.

수집 경로는 이미 있다:
- `tour_poi_arrival_profiles`에 `meeting_point`가 이미 있으니 **이미지 컬럼 하나** 추가
- **기사가 첫 방문 때 한 번 찍으면 그 POI는 영구 해결**
- 검수 게이트는 `facility_pins`의 `is_verified` 패턴을 **그대로 복제** (새로 설계할 것 없음)

### D-4. 리스크

- **경계 소실** — 밝은 사진 + 밝은 카드면 경계가 사라진다. 스킨별로 사진 하단에 `--tr-home-card-line` 한 줄을 깔지 결정 필요. **게이트가 못 잡는 종류의 결함.**
- **LCP/CLS** — 홈은 가장 많이 열리는 화면. 높이 고정(144px) + priority.
- **오프라인** — B13. 다음 스팟 사진 **1장만** SW 프리페치하는 규칙 필요. 없으면 터널에서 히어로가 빈다.
