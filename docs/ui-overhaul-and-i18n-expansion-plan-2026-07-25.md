# A. UI 전면 재편 플랜

## A-0. 진단 — 이번 복구 작업에서 실제로 관찰한 것

추상적 심미성 논의가 아니라, 이번에 코드를 읽으며 **실측한 구조적 결함**에서 출발한다.

| 관찰 | 근거 | 함의 |
|---|---|---|
| 역할 분기가 렌더 시점에 산발적 | P1-1(지도), P1-4(빈 상태)가 같은 실수 — `viewerRole`이 스코프에 있는데 안 씀 | 역할은 **컴포넌트 경계**여야지 if문이면 안 됨 |
| 타이포 스케일이 두 갈래 | `.tr-*` 클래스 7종 vs `text-[Npx]` 하드코딩 58곳 | 설정이 화면 전체를 못 움직임(P1-6에서 절반만 해결) |
| CJK 줄바꿈이 기본값에 방치 | P1-5 — 문제 지점에 `break-all`조차 없었음 | 토큰이 아니라 **기본값**이 적이다 |
| 셸이 4종 각자 진화 | RoomShell / GuideConsole / Cockpit / PlanEditor — 홈 버튼 유무가 제각각 | 셸 공통 계약 부재 |

## A-1. 사용 환경별 분리 설계

| 환경 | 제약 | 설계 원칙 |
|---|---|---|
| **차량 내 가이드** | 한 손·짧은 시선·흔들림·햇빛 | 탭 타깃 최소 48px, 정보 밀도 최소, 대비 최대. 화면당 **주 동작 1개**. 현재 Cockpit이 가장 근접 — 이걸 기준으로 GuideConsole을 끌어올린다 |
| **손님** | 탐색 위주·낯선 앱·다국어 | 읽기 우선, 동작은 확인 가능해야 함. 빈 상태·오류가 **정직**해야 함(P0-4에서 배운 것) |
| **관제센터** | 정보 밀도·데스크톱 병행 | 표 중심, 한 화면에 많이. 단 CJK 줄바꿈 규칙(P1-5) 필수 |

## A-2. 로드맵

- **1단계 — 기반 통일 (선행 필수)**
  - `text-[Npx]` 58곳을 `.tr-*` 토큰으로 수렴 → P1-6 폰트 스케일이 전 화면에 작동
  - 셸 공통 계약 정의: 모든 셸은 `homeHref`·역할·로케일을 받는다
  - ⚠️ **일괄 치환 금지.** 이번 사고의 원인이다. 화면 단위로 나눠 각각 검증·커밋
- **2단계 — 역할 경계 정리**
  - `<GuestOnly>` / `<OperatorOnly>` 경계 컴포넌트 도입 → P1-1/P1-4류 재발 차단
- **3단계 — 환경별 밀도 프리셋**
  - 가이드=저밀도·대형, 관제=고밀도. P1-6 스케일 변수를 밀도까지 확장
- **4단계 — 심미성**
  - 1~3단계 후에만. 구조가 흔들리는 상태의 스킨 작업은 낭비

# B. 다국어 확장 플랜 (러시아어·프랑스어·독일어·이탈리아어)

## B-0. 현황 — 실측

| 항목 | 실측값 |
|---|---|
| `messages/*.json` | 10개 (en, ko, ja, es, zh, zh-TW, **fr, de, it, ru**) — 감사가 4개 추가 |
| `middleware.ts SUPPORTED_LOCALES` | 10개 — 이미 라우팅됨 |
| `tour_product_pages` (상품 상세 콘텐츠) | **6개 로케일만** (en/ko/ja/es/zh/zh-TW) × 34 슬러그 · **fr/de/it/ru 0행** |
| `match_pois` (POI 이름) | 124개 중 **75개**에 zh/zh-TW/ja/es · fr/de/it/ru 없음 |

→ **UI 문자열은 준비됐고 콘텐츠는 없다.** P1-7의 404가 정확히 이 간극이었다(→ 영어 폴백으로 처리).

## B-1. 번역 순서 (권장)

1. **UI 문자열 검수** — 이미 있는 `messages/{fr,de,it,ru}.json`은 기계 번역 상태로 추정. 원어민 검수 **먼저**. 여기가 틀리면 콘텐츠 품질과 무관하게 앱이 싸구려로 보인다.
2. **POI 이름** (`match_pois.names_other_locales`) — 분량 최소, 효과 최대. **P1-8 용어사전이 이 데이터를 그대로 강제**하므로, 여기만 채우면 자막·채팅·일정 전부가 자동으로 정확해진다.
3. **상품 상세** (`tour_product_pages`) — 34슬러그 × 4언어 = 136건. 가장 비쌈. 매출 상위 슬러그부터.
4. 랜딩·리스트 등 나머지 고객 노출면.

## B-2. 방법

- **기계 번역 + 원어민 감수** 2단계. 순수 기계 번역은 "원어민 수준" 기준에 미달.
- **고유명사는 번역 대상에서 제외** — P1-8 글로서리가 이미 강제 치환한다. 번역가에게는 placeholder 상태로 전달하면 오역이 원천 차단된다.
- 톤: 상품 상세는 마케팅 문체, 투어룸은 안내 문체 — 번역가에게 **문체 지침을 분리 제공**.

## B-3. 폴백 규칙 (이미 구현됨, P1-7)

- 상품 상세: 콘텐츠 없는 로케일 → **영어 정식 URL로 308**. 404도 빈 페이지도 아님.
- 일정/POI: `[locale] → 기본언어 → en → 원문` (P0-5 `pickLocalizedName`)
- 신규 로케일 추가 시 **테스트가 강제**한다(`__tests__/app/tourProductLocaleRouting.test.ts`) — 화이트리스트나 폴백 중 하나를 선언하지 않으면 CI 실패.

## B-4. 선결 조건

- 4개 언어를 **고객에게 노출하기 전에** 최소 (1)UI 검수 + (2)POI 이름은 끝나야 한다. 현재 상태로 노출하면 상세 페이지가 전부 영어로 폴백되어 "번역된 척하는 사이트"가 된다.
