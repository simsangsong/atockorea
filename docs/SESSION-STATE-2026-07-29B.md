## 🔴 이번 라운드에서 배운 것 — 다음 사람이 읽어야 할 것

### 1. 스크린샷으로 안 보이는 결함이 있다
설치 배너가 입력창을 덮은 건 **배너도 입력창도 둘 다 화면에 있어서** 컷으로는 정상이다.
겹침은 **z 순서에만** 존재한다. → `elementFromPoint` 히트 테스트가 필요하다.
`.tmp/probe-occlusion.mjs` 패턴을 재사용할 것.

### 2. "코드에 있다"와 "작동한다"는 다르다 — 순서 때문에
`east-signature-nature-core`는 **이미 차단 목록에 있었다.** 그런데 면제 한 줄이
차단 검사보다 **위에** 있어서 차단이 카탈로그에는 영영 적용되지 않았다.
**차단 목록에 한 번 더 넣어도 안 고쳐진다.** 게이트는 개별 사실이 아니라
**"차단 = 카탈로그 숨김이 모든 슬러그에서 일치"**로 걸어야 한다.

### 3. 주석이 전제를 적어 두면, 그 전제를 검사하라
칩 줄 페이드 주석: *"끝까지 스크롤하면 마지막 칩이 페이드 전에 끝난다."*
**성립한 적이 없었다.** flex 줄은 마지막 아이템 뒤에 아무것도 두지 않는다.
설계는 옳았고 **전제가 조용히 거짓**이었다.

### 4. EventSource는 429를 못 본다
비-200이면 브라우저가 **영구 중단**한다. 그리고 `useTourRoomChannel`엔 전송이
**Realtime·SSE 둘뿐**이고 폴링 클라이언트가 없다.
→ **이 라우트에서 거부 = 방 침묵.** 상한은 반드시 **스로틀**(200 + 긴 `retry:`)이어야 한다.

### 5. 워크트리 dev 서버는 `pkill`로 안 죽는다
이번 세션에 **세 번** stale CSS를 서빙했고, 증상이 "수정이 아무 효과 없음"이라 위험하다.
`.tmp/devup.sh` 사용 — 포트로 죽인다.

### 6. Python heredoc으로 정규식·`\n`이 든 파일을 고치지 말 것
두 번 깨졌다(테스트 파일 안에 실제 개행이 들어감). Edit 도구를 쓸 것.
(기존 기록 "node -e 금지"와 같은 함정이다.)

## 🔴 이번에 배운 것 — 앞의 6개에 이어서

### 7. 티켓 제목을 믿지 말고 재라
**K5는 "동시성 상한"이 아니었다.** 한 메시지 = LLM **1회**(로케일 무관).
진짜 노출은 완전히 다른 것이었다: `8초 × 사다리`를 insert **앞에서** 기다렸고
`maxDuration`이 없어서 **플랫폼이 죽이면 메시지가 사라진다**.
**스코핑 없이 착수했으면 없는 문제에 상한을 걸었을 것이다.**

### 8. 플랜의 경고도 사실 확인 대상이다
**K3의 "K1a와 같은 파일" 경고는 거짓**이었다. 그대로 믿었으면 있지도 않은 리베이스를 준비했다.
→ 정정을 **주석이 아니라 테스트**로 넣었다. 주석은 아무도 안 멈춘다.

### 9. 감성 레이어가 대비를 깎으면 그건 감성이 아니다
N2 다크에서 색조 없는 기준선이 **이미 4.39**였다. 층을 얹으니 **3.87**.
줄여도 기준선 밑. → **다크는 통째로 제외.** 회귀 0이 유일하게 정직한 값이다.

### 10. 스캐너를 고치는 게 스캔 결과를 훑는 것보다 싸다
X1 잔여를 손으로 훑기 전에 스캐너를 봤더니 **135건이 애초에 고칠 수 없는 것**이었다.
그리고 **코드모드는 스캐너가 가리키는 걸 고친다** — 잘못된 히트는 노이즈가 아니라 **잘못된 수정 지시**다.
