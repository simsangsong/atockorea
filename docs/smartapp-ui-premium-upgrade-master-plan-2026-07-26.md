### A-4. 시각 결함 실측 (촌스러움의 해부)

1. **타입 스케일 위반 약 290건** — `tr-*` 6클래스 선언(`tour-room-theme.css:125-159`, "이 스케일 외 금지" U-D6) 밖에서 `text-sm` 89 + `text-base` 34 + `text-xs` 44 + 임의 `text-[Npx]` 60 + `text-lg~3xl` 63. **글자 크기 5단계 슬라이더가 화면 절반에 안 먹는다.**

## §C. 바인딩 결정 (U4-D 시리즈 — 승인 대상)

- **U4-D1 — 스태프 대화창 단일화.** 가이드·기사의 대화 표면은 **RoomShell 채팅 하나**다. 콕핏 내장 채팅(버블 영역+입력독)은 **공용 ChatFeed/Composer 임베드로 교체**하고, 콕핏 고유 가치(대형 타겟·자동 TTS·원버튼 시그널·내비 행)는 **"주행 모드" = 같은 채팅 화면의 표시 상태**로 재정의한다. 별도 대화 구현 2개를 유지하지 않는다. 라우트 `/tour-mode/guide`·`/tour-mode/driver`는 진입 별칭으로 존치(토큰 체계 상이: 가이드=tour-date 스코프, 기사=driver scope+차량 PIN — 기존 인증 불변).
- **U4-D2 — 스태프 셸 하단 4탭.** `[대화] [좌석·명단] [운행] [설정]`. 대화=룸 리스트(프라이빗 1건이면 리스트 스킵하고 바로 채팅), 좌석·명단=`GuideSeatDashboard` 승격(**사용자 요청의 "바텀바 좌석명단 아이콘"**), 운행=콕핏 도구(내비 행·체크리스트·시그널·지출/정산 — 역할 능력 플래그로 노출 제어), 설정=테마·언어·설명서. 손님 5탭 문법(홈·채팅·지도·오늘·설정)은 **불변** — 손님 바텀바에 좌석 탭을 추가하지 않는다(근거: "좌석 터치→해당 고객과 단독 대화"는 스태프 행위이고, 손님 간 DM 인프라는 의도적으로 없음).
- **U4-D3 — 좌석 터치→1:1 대화 = 내비게이션이지 새 채널이 아니다.** 좌석 탭 → `assignment.booking_id` → 그 예약의 룸 채팅(`/tour-mode/room/{bookingId}?rt=…`)으로 이동. 룸=예약당 구조라 **이것이 곧 단독 대화**다. 새 DM 스키마·새 팬아웃 라우트 금지(`broadcast/route.ts:29-38` "두 번째 팬아웃을 만들지 않는다" 기존 결정 준수). 좌석 액션시트에 [대화 열기]·[이 손님에게만 공지](=`bookingIds:[…]` 타겟 발송) 2액션 추가.
- **U4-D4 — 손님에게 개인/전체 구분 비노출 유지** (기존 B3-D5, `messageTarget.ts:14-16`). 손님 화면에 "귓속말" 표기를 만들지 않는다. 손님의 좌석 보기는 읽기전용 + `maskGuestName()` 마스킹(C-1 PII 유지), 진입은 서랍·홈 타일(조인투어에서만 의미).
- **U4-D5 — 서랍 = 카톡 서랍 문법.** 헤더 우측 메뉴 버튼 → 우측 슬라이드 드로어: ① 모아보기(사진/동영상 그리드·파일 리스트·링크 리스트 — `tour_room_messages`의 `input_kind image|file` + URL 감지 집계) ② 일정·공지 바로가기 ③ 기능 그리드 ④ 대화상대(아바타·이름·역할·좌석 뱃지, 스태프에겐 행 탭=해당 룸 대화) ⑤ 동행 초대(기존 `CompanionInviteCard` 이관). 손님·스태프 공용, 역할별 항목 차등.
- **U4-D6 — 아이콘 규율.** 사이즈 토큰 5단 고정: **14(메타) / 16(칩·리스트) / 18(버튼 표준) / 22(헤더·탭) / 26(콕핏·타일)** — `icons.ts`에 `TR_ICON` 상수로 내보내고 254건 전수 스냅. `strokeWidth` 표준 1.75(16px 이상)·2(14px). lucide 직수입 25파일 → 배럴 경유로 통일. **이모지 크롬 전면 퇴출**(§A-4-4 목록 전건 lucide 교체) — 단 메시지 콘텐츠·리액션(`👍❤️😂😮🙏`)·프리셋 "전송 텍스트"는 콘텐츠이므로 유지하되, **칩 UI 렌더에서는 이모지 대신 아이콘**을 쓴다.
