## §1 왜 다시 짓는가

v1~v4는 **첫 판에 땜빵을 얹는 방식**이었다. 반려가 올 때마다 스펙 한 줄, 필터 한 줄을
고쳤고, 그래서 결함이 옮겨다니기만 했다. 마지막 두 개가 그 증거다.

| 결함 | 진짜 원인 | 눈으로는 안 잡힘 |
|------|-----------|------------------|
| 클로즈업이 대상을 잘라먹음 | 배율을 **대상 크기에 맞춰** 잡아서 크롭 창이 대상보다 작다. 달마대사: 대상 800px, 크롭 창 496px — 어느 순간에도 40%가 화면 밖 | 시작/끝 프레임만 보면 "훑는 것"처럼 보인다 |
| 걷는 구간이 느림 | 배속은 **정상 작동**(34비트 전부 계획 일치, 불일치 0). 내가 배속 값을 낮게 잡았을 뿐 — 108계단 36초를 2.4배로 눌러도 15초다 | 배속이 걸려 있으니 "했다"고 착각 |

**교훈: 눈으로 확인하는 검수는 이 두 종류를 못 잡는다.** 그래서 v5는 규칙을
게이트로 박고, 게이트가 통과해야만 렌더한다.

## §3 페이싱 규칙 (v5 신설)

배속을 비트마다 감으로 정하지 않는다. **구간의 성격이 배속을 정한다.**

| 성격 | 배속 | 근거 |
|------|------|------|
| 볼 것 없는 이동 (계단·흙길·담장길) | **8x** | 길이 이어진다는 것만 보이면 된다 |
| 볼 것 있는 이동 (상가·사찰 경내) | **4x** | 분위기는 남기되 머물지 않는다 |
| 교차로 진입 | **1.5x**, 최대 4초 | 감속 자체가 "여기서 갈린다"는 신호 |
| 하이라이트 이동 (다리·대나무길·오션뷰) | **1x** | R7 |
| 강조 대상 | 정지 4.5초 | R4 |
| 스냅샷 | 2.6초 | R5 |

🔴 **불변식: 1배속 구간 총합이 전체의 40%를 넘지 않는다.** 넘으면 게이트가 막는다.

## §4 클로즈업 — 포함 불변식

**크롭 창은 언제나 대상 사각형을 8% 여백과 함께 포함한다.**

```
zoom  = clamp( min(1920/(fw*1.16), 1080/(fh*1.16)), 1.10, 2.40 )
cw,ch = 1920/zoom, 1080/zoom              # 구성상 cw>=fw*1.16, ch>=fh*1.16
xRange = [ fx+fw-cw+m , fx-m ] ∩ [0, 1920-cw]     # 창이 가질 수 있는 자유도
yRange = 같은 식
시작 = xRange.min, yRange.min   (좌상)
끝   = xRange.max, yRange.max   (우하)
```

자유도가 없으면 정지 유지 — 잘라먹느니 안 움직인다.
"좌상→우하" 느낌은 **남은 자유도 안에서의 드리프트**로 만든다. 대상을 지나쳐 가는 게 아니다.

## §5 게이트 (렌더 전에 통과해야 한다)

1. **연속성** — 같은 클립 안 시간 점프 0, 클립 전환엔 transition (기존)
2. **클로즈업 포함** — §4 식으로 계산한 크롭 창이 t=0과 t=1 양쪽에서 focus 사각형을 포함
3. **페이싱** — 1배속 총합 ≤ 40%, 한 비트 출력 길이 ≤ 20초
4. **렌더 후 길이 대조** — 실제 인코딩 길이 vs 계획값 (배속이 실제로 걸렸는지)

게이트 2·3이 v4에서 놓친 두 결함을 정확히 잡는다.
