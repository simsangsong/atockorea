## §A 문제 — 사장님 말 ↔ 계측된 현실

| 사장님 인식 | 코드 현실 (2026-08-08 조사) |
|---|---|
| 손님 100명 = 링크 100개 복사 | 링크는 **예약(팀) 단위**다. 100명 ≈ 25~35예약. 그래도 개별 복사면 25~35회 — 문제 유효 |
| 기사도 손님별 매칭 링크를 복사 | **이미 아니다.** 기사 링크는 (투어,날짜)당 1개고, 그 링크 하나로 그날 전 팀 목록→팀별 콕핏 진입이 완성돼 있다(`DriverConsole.tsx:198-239`, `driver/overview` 가 그날 예약 전부 반환). 오해의 근원 = 어드민 룸 관리 화면이 **예약 행마다** [별도 기사] 버튼을 놓아 손님별 발급처럼 보임(`OpsRoomManager.tsx`) |
| 링크가 너무 길어 스캠 같다 | 실측 **345자**. 원인 = 토큰이 자기완결(예약ID+**손님 이름**+만료를 base64 로 URL 에 통째로 + HMAC 서명 64자, `lib/tour-room/token.ts`). 이름이 URL 에 실리는 PII 문제 동반 |
| 일일이 왓츠앱 전달 | 일괄 경로가 **이미 둘 다 있다**: 이메일 원버튼(bulk-invite/bulk-message) + 왓츠앱 순차 [다음 열기](클릭당 1탭, 팝업차단 안전). 남은 마찰은 클릭 수가 아니라 **말풍선 속 345자 링크의 모양** |
| — | 🔴 **OTA 예약 일부는 이메일로 원천 도달 불가**(마스킹/프록시/부재 — `bulkInvite.ts` 가 `skippedNoEmail` 을 세고 토스트로 보고). 그 손님들의 채널은 왓츠앱·현장뿐 |
| — | 🔴 **D-1 자동 발송 크론이 살아 있다**(`vercel.json` 매일 18:00 KST → `emails/reminders` → `dispatchTomorrowsRooms()`). 「투어룸 자동 발송 금지」 결정(2026-08-03)과 충돌 — 지금은 `NEXT_PUBLIC_TOUR_MODE_V1` OFF 라 조용할 뿐, **플래그 켜는 순간 자동 발송이 시작된다** |

## §B 재사용 자산 감사 — 새로 만들 것은 「코드」와 「문」뿐

| 자산 | 위치 | 상태 |
|---|---|---|
| 초대 원장 `tour_room_invites` | DB | token_hash·revoke 체계 완비 — **컬럼 하나 추가로 코드 원장 겸용 가능** |
| 명단에서 이름 골라 입장(claim) | `/tour-mode/join/*` + `bulkInvite.ts` | 완성. 현재 "이메일 없는 예약용 운영자 폴백"으로 강등돼 있음 |
| `bookings.booking_reference` | UNIQUE + partial index | `A2C-`+8hex. **빌더 예약만 채워짐**, 룸 진입 미연결 (조회처는 챗봇 1곳) |
| `bookings.external_booking_id` | UNIQUE(source,id) | Klook/Viator/GYG/KKday 예약번호 — 손님이 바우처로 **이미 갖고 있는 번호**. 룸 미연결 |
| 이메일 일괄 발송 | `bulk-invite`·`bulk-message` | 완성 (미리보기→발송, 수신자별 토큰 발급) |
| 왓츠앱 순차 발송 | `OpsManifestView` + `wa-deep-link.ts` | 완성 (`{room_link}` 자리에 즉석 토큰 발급) |
| 기사 PIN 게이트 | `checkDriverPin` (차량번호 뒤 4자리) | "짧은 식별자 + 확인" 패턴의 작동하는 선례 |
| 현장 재합류 QR + rate limit | `/reinvite` (3/min·12/hr) | rate limit 패턴 재사용처 |

발송 채널·인증·명단·원장 전부 재사용. **URL 단축기는 레포에 없다 — 이번에 만드는 것이 그것이다.**

## §C 설계 — 항공사 체크인 모델

한 문장: **예약 1건 = 코드 1개. 코드는 클릭하면 링크가 되고, 말하면 입장 번호가 된다.**
(항공사와 같다: 예약번호 + 이름으로 체크인. 손님에게 이미 익숙한 모델이라 스캠 의심이 원천 소멸.)

### C-1 코드
- 형식: **8자, 혼동 문자(0/O/1/I) 제외 알파벳**, 표기는 `K7M2-P9QX` (저장은 하이픈 없이)
- 단위: **예약당 1개** — 일행이 공유("우리 코드 K7M2"), 100명이어도 코드는 예약 수만큼
- 원장: `tour_room_invites` 에 `short_code` 컬럼(UNIQUE, additive DDL) — 예약당 활성 코드 1개, 재발급(회전) 시 구코드 revoke
- 수명: 발급 시점 ~ 투어일 KST+24h(기존 토큰과 동일). 예약 취소 시 revoke

### C-2 문 두 개 (같은 코드, 두 진입)
1. **클릭 문** `atockorea.com/r/K7M2P9QX` (~30자)
   서버가 원장 조회 → 유효하면 **기존 토큰을 그 자리에서 발급해 리다이렉트** → 기존 join/세션 기계 무변경.
   긴 토큰은 이제 주소창에 잠깐 스칠 뿐, **메시지·미리보기·로그에서 소멸** (이름 PII 도 함께 소멸).
2. **입력 문** `atockorea.com/room` (짧은 고정 주소, 기존 `/tour-mode` 게스트 폼 업그레이드)
   코드 입력 → **명단에서 자기 이름 탭**(기존 claim 화면 재사용) → 입장.
   현재 폼의 "예약 ID(UUID 36자) + 이메일" 입력은 폐기.

### C-3 끝그림 — 발송 자체의 소멸
**입력 문이 OTA 예약번호(`external_booking_id`)도 인정**하면, Klook 손님은 바우처에 이미 있는
번호로 들어온다. OTA 리스팅 안내문에 한 줄("투어 당일 atockorea.com/room 에서 Klook 예약번호 입력")을
넣는 순간 — **신규 예약은 보낼 것 자체가 없다.** 이메일 마스킹 예약(§A 도달 불가 그룹)도 이 문으로 해결.

### C-4 기사 쪽 — 코드 작업 거의 없음
- 구조는 이미 정답(하루 1링크 → 전 팀). 이번 플랜에서는 ① 그 링크도 짧은 링크로 ② 어드민의
  예약 행별 [별도 기사] 버튼을 **날짜 레벨 헤더의 버튼 1개로 이동**(오해의 근원 제거)
- 기사에게 가는 메시지는 하루 1통: "오늘 콘솔 → atockorea.com/r/XXXX · 차량번호 뒤 4자리로 입장"

### C-5 전/후 비교

| | 지금 | 개편 후 |
|---|---|---|
| 손님에게 가는 것 | 345자 토큰 링크 | "atockorea.com/room 에서 **K7M2-P9QX**" (+30자 클릭 링크) |
| 100명(≈30예약) 배포 | 개별 복사 30회 or 일괄(긴 링크) | 이메일 **버튼 1번** + 왓츠앱 순차(짧은 문구) → 끝그림: **0번** |
| 이메일 없는 OTA 손님 | 도달 불가(운영자 폴백) | 바우처 번호로 셀프 입장 |
| 기사 | 오해: 손님별 매칭 복사 | 하루 1개 재확인 + 버튼 위치로 오해 제거 |
| URL 속 손님 이름 | base64 로 노출 | 소멸 |
| 스캠 인상 | 토큰 뭉치 | 브랜드 도메인 + 항공사식 코드 |

## §D 사장님 결정 — ✅ 확정 (2026-08-08)

1. **OTA 예약번호 직접 입장: 허용 — Klook·GYG·Viator 전부 포함.** ("다 포함" — `external_booking_id` 는
   source 무관 매칭이므로 KKday 등 파서가 커밋하는 모든 OTA 소스가 자동 포함된다)
2. **자동 발송은 보류 — 수동 유지.** 단 **템플릿에 고객별 링크 자동 prefill 은 유지·강화**
   (기존 bulk-message/WA 의 `{room_link}` 즉석 발급이 이미 이것 — 이번에 그 자리에 **짧은 링크**가 들어가게 바꾼다).
   D-1 자동 크론은 발송하지 않도록 정리.
3. **왓츠앱 표준 문구는 사장님이 추후 제공** — 프라이빗·택시투어·스몰그룹·shore excursion 별로 안내가 다름.
   → 이번 구현은 기존 기본 문구 + `{room_link}`/`{entry_code}` 자리표시자 체계까지. **상품 유형별 문구 슬롯**이
   기존 "투어별 문구 오버라이드"로 충분한지 P2 에서 확인하고, 부족하면 유형 레벨 기본값 슬롯을 추가.
4. 코드 회전 권한 — 어드민 (기존 links 라우트 권한 그대로)

## §F 보안·엣지

- 코드 엔트로피 40bit(8자 base32) + 시도 제한 + 실패 응답 균일화(코드 존재 여부 비노출)
- 클릭 문 리다이렉트가 발급하는 토큰은 기존 만료·스코프 규칙 그대로 — 보안 모델 무변경
- 이름 선택 뒤 세션은 기존 참가자 세션 기계 그대로 (unsend 의 참가자 스탬프 매칭 등 무영향)
- 코드 회전 시 구코드 즉시 revoke — 원장에 감사 추적
- 미리보기·로그·왓츠앱 말풍선에서 PII 제로 확인을 P4 게이트에 포함
